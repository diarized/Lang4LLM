# BS-S-008: Remove Duplicates from List

**Tier**: Simple
**Category**: Data Structures
**Estimated LOC**: 10-15

## Task Description

Return a new list containing the same elements as the input but with all duplicate values removed, preserving the original order of first occurrences.

## Requirements

### Functional Requirements

1. Accept a list of integers as input
2. Return a new list where each value appears at most once
3. The order of elements in the output must match the order of their first occurrence in the input
4. The original input list must not be modified

### Input Specification

- **numbers**: A list of integers (may be empty or contain duplicates)
- **Return**: A list of integers with duplicates removed, preserving first-occurrence order

### Constraints

- List length: 0 to 10,000 elements
- Elements can be any valid integer (positive, negative, zero)
- Time complexity: O(n) average case
- Output list length is at most equal to the input list length

## Examples

### Example 1: List with duplicates

**Input**: [1, 2, 2, 3, 1, 4]
**Output**: [1, 2, 3, 4]
**Explanation**: 2 and 1 each appear twice; only first occurrences are kept, in original order

### Example 2: No duplicates

**Input**: [5, 3, 8, 1]
**Output**: [5, 3, 8, 1]
**Explanation**: All elements are unique; output equals input

### Example 3: All duplicates

**Input**: [7, 7, 7, 7]
**Output**: [7]
**Explanation**: All elements are the same; output contains the single unique value

### Example 4: Empty list

**Input**: []
**Output**: []
**Explanation**: An empty list has no elements to deduplicate

### Example 5: Negative numbers with duplicates

**Input**: [-1, -2, -1, 0, -2]
**Output**: [-1, -2, 0]
**Explanation**: First occurrences of -1, -2, and 0 are retained in order

## Test Cases

### Required Coverage

- List with several duplicates scattered throughout
- List with no duplicates (output equals input)
- List where all elements are identical
- Empty list
- List with negative numbers and zero
- Single element list
- Duplicates at beginning and end

### Minimum Test Count

5 test cases

## Success Criteria

- [ ] Removes all duplicate occurrences, keeping only the first
- [ ] Preserves the relative order of first occurrences
- [ ] Handles empty list correctly
- [ ] Does not modify the original input list

## Notes

Common mistakes:
- Preserving last occurrence instead of first occurrence
- Altering the order of elements
- Modifying the input list in place rather than returning a new one
- Quadratic implementations (scanning for duplicates with a nested loop) are acceptable at small scale but inefficient for large inputs
