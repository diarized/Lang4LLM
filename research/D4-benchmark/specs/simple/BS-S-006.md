# BS-S-006: Check if Array is Sorted

**Tier**: Simple
**Category**: Data Structures
**Estimated LOC**: 5-15

## Task Description

Determine whether a list of integers is sorted in non-decreasing order (each element is less than or equal to the next).

## Requirements

### Functional Requirements

1. Accept a list of integers as input
2. Return true if the list is sorted in non-decreasing order, false otherwise
3. A list with zero or one element is always considered sorted
4. Equal adjacent elements are allowed (non-strict ascending)

### Input Specification

- **numbers**: A list of integers (may be empty)
- **Return**: A boolean value (true if sorted non-decreasingly, false otherwise)

### Constraints

- List length: 0 to 10,000 elements
- No sorting operations allowed — only inspection
- Time complexity: O(n) where n is list length
- Space complexity: O(1)

## Examples

### Example 1: Sorted ascending

**Input**: [1, 2, 3, 4, 5]
**Output**: true
**Explanation**: Each element is less than the next; the list is in non-decreasing order

### Example 2: Not sorted

**Input**: [1, 3, 2, 4]
**Output**: false
**Explanation**: 3 followed by 2 violates non-decreasing order

### Example 3: Equal adjacent elements

**Input**: [1, 2, 2, 3]
**Output**: true
**Explanation**: Equal adjacent elements are permitted in non-decreasing order

### Example 4: Single element

**Input**: [7]
**Output**: true
**Explanation**: A single-element list is trivially sorted

### Example 5: Empty list

**Input**: []
**Output**: true
**Explanation**: An empty list is trivially sorted

## Test Cases

### Required Coverage

- Already sorted list (strictly ascending)
- List with equal adjacent elements
- Unsorted list (violation at beginning)
- Unsorted list (violation at end)
- Single element list
- Empty list
- All elements equal
- Descending order list

### Minimum Test Count

5 test cases

## Success Criteria

- [ ] Returns true for sorted lists including those with equal adjacent elements
- [ ] Returns false on first detected ordering violation
- [ ] Handles single-element and empty lists correctly
- [ ] Does not modify the input list

## Notes

Common mistakes:
- Using strict less-than instead of less-than-or-equal (rejects equal adjacent elements)
- Off-by-one errors when iterating pairs (missing last pair or going out of bounds)
- Treating empty list or single-element list as invalid input
