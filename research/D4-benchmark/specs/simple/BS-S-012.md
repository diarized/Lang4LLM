# BS-S-012: Get Last Element

**Tier**: Simple
**Category**: Data Structures
**Estimated LOC**: 5-10

## Task Description

Return the last element of a list of integers, or a null/none value if the list is empty.

## Requirements

### Functional Requirements

1. Accept a list of integers as input
2. Return the last element of the list if the list is non-empty
3. Return null/none (or an equivalent absent value) if the list is empty
4. Do not modify the list

### Input Specification

- **numbers**: A list of integers (may be empty)
- **Return**: The last integer in the list, or null/none if the list is empty

### Constraints

- List length: 0 to 10,000 elements
- Elements can be any valid integer (positive, negative, zero)
- No removal or mutation of the list is allowed
- Time complexity: O(1) preferred; O(n) is acceptable

## Examples

### Example 1: Standard list

**Input**: [1, 2, 3, 4, 5]
**Output**: 5
**Explanation**: 5 is at the final position in the list

### Example 2: Single element

**Input**: [42]
**Output**: 42
**Explanation**: The only element is also the last element

### Example 3: Empty list

**Input**: []
**Output**: null/none
**Explanation**: There is no last element in an empty list; return an absent value indicator

### Example 4: Negative numbers

**Input**: [-10, -3, -7]
**Output**: -7
**Explanation**: -7 is the last element; negative values are valid

### Example 5: List ending in zero

**Input**: [5, 3, 1, 0]
**Output**: 0
**Explanation**: Zero is a valid last element; it must not be confused with an absent value

## Test Cases

### Required Coverage

- Non-empty list with multiple elements
- Single element list
- Empty list (null/none return)
- Last element is zero (must not be mistaken for absence)
- Last element is negative
- List where first and last elements differ

### Minimum Test Count

5 test cases

## Success Criteria

- [ ] Returns the correct last element for non-empty lists
- [ ] Returns null/none for an empty list
- [ ] Does not confuse zero or negative values with an absent result
- [ ] Does not modify the input list

## Notes

Common mistakes:
- Returning 0 as the "empty" sentinel (incorrect when 0 is a valid element)
- Off-by-one error (returning second-to-last element)
- Throwing an exception for empty input instead of returning a null/none value
- Iterating through the entire list when direct index access is possible
