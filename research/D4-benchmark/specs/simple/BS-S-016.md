# BS-S-016: Check Power of Two

**Tier**: Simple
**Category**: Algorithms
**Estimated LOC**: 5-10

## Task Description

Determine whether a given integer is a power of two (that is, equal to 2 raised to some non-negative integer exponent), returning a boolean result.

## Requirements

### Functional Requirements

1. Accept a single integer as input
2. Return true if the integer equals 2^k for some non-negative integer k (k >= 0)
3. Return true for the value 1, since 2^0 = 1
4. Return false for any integer that is zero, negative, or not expressible as a power of two

### Input Specification

- **n**: An integer (any value, including zero and negatives)
- **Return**: A boolean value (true if n is a power of two, false otherwise)

### Constraints

- Input range: any valid integer
- 1 is considered a power of two (2^0)
- Zero and negative numbers are not powers of two
- Time complexity: O(log n) or better

## Examples

### Example 1: Power of two

**Input**: 8
**Output**: true
**Explanation**: 8 = 2^3

### Example 2: Not a power of two

**Input**: 6
**Output**: false
**Explanation**: 6 cannot be expressed as 2^k for any integer k

### Example 3: One (edge case)

**Input**: 1
**Output**: true
**Explanation**: 1 = 2^0; 1 is a power of two

### Example 4: Zero (edge case)

**Input**: 0
**Output**: false
**Explanation**: Zero is not a power of two

### Example 5: Negative number

**Input**: -4
**Output**: false
**Explanation**: Negative numbers are not powers of two

### Example 6: Large power of two

**Input**: 1024
**Output**: true
**Explanation**: 1024 = 2^10

## Test Cases

### Required Coverage

- n = 1 (2^0, edge case)
- n = 2 (smallest prime power)
- Several larger powers of two (4, 8, 16, 1024)
- Non-power such as 3, 6, 7, 12
- n = 0
- Negative n

### Minimum Test Count

5 test cases

## Success Criteria

- [ ] Returns true for all positive powers of two including 1
- [ ] Returns false for all integers that are not powers of two
- [ ] Returns false for zero
- [ ] Returns false for negative numbers

## Notes

Common mistakes:
- Treating 0 as a power of two (it is not)
- Forgetting that 1 is a power of two (2^0)
- Off-by-one errors in iterative doubling approaches
- Bit-manipulation shortcut (n & (n - 1) == 0) is efficient but must guard against n <= 0 first
