# BS-S-007: Find Minimum in List

**Tier**: Simple
**Category**: Data Structures
**Estimated LOC**: 5-15

## Task Description

Return the smallest integer from a non-empty list of integers, considering both positive and negative values.

## Requirements

### Functional Requirements

1. Accept a non-empty list of integers as input
2. Return the minimum (smallest) value in the list
3. Handle negative numbers correctly
4. Handle lists with a single element

### Input Specification

- **numbers**: A non-empty list of integers (at least one element)
- **Return**: An integer representing the minimum value

### Constraints

- List length: 1 to 10,000 elements
- List will always contain at least one element (empty list is not a valid input)
- No built-in min() functions allowed
- Time complexity: O(n) where n is list length
- Space complexity: O(1)

## Examples

### Example 1: Positive numbers

**Input**: [3, 7, 2, 9, 1]
**Output**: 1
**Explanation**: 1 is the smallest number in the list

### Example 2: Negative numbers

**Input**: [-5, -2, -8, -1]
**Output**: -8
**Explanation**: -8 is the smallest (most negative) value

### Example 3: Mixed positive and negative

**Input**: [-3, 5, -1, 2]
**Output**: -3
**Explanation**: -3 is the smallest value in the mixed list

### Example 4: Single element

**Input**: [42]
**Output**: 42
**Explanation**: The only element is both minimum and maximum

### Example 5: All same values

**Input**: [4, 4, 4, 4]
**Output**: 4
**Explanation**: All elements equal; the minimum is that common value

## Test Cases

### Required Coverage

- List with all positive numbers
- List with all negative numbers
- List with mixed positive and negative numbers
- Single element list
- List with duplicate minimum values
- List where minimum is at the end
- List where minimum is at the beginning

### Minimum Test Count

5 test cases

## Success Criteria

- [ ] Finds the correct minimum value
- [ ] Handles all-negative lists correctly
- [ ] Works with single-element lists
- [ ] Handles lists where all elements are equal
- [ ] Completes in O(n) time

## Notes

Common mistakes:
- Initializing the running minimum to 0 (fails for all-positive lists where min > 0, or all-negative lists)
- Not seeding the running minimum from the first list element
- Using wrong comparison direction (finding max instead of min)
