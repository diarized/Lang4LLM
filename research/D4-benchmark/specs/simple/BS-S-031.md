# BS-S-031: Integer Square Root

**Tier**: Simple
**Category**: Mathematics
**Estimated LOC**: 10-15

## Task Description

Return the integer square root of a non-negative integer, defined as the largest integer whose square is less than or equal to the input. Do not use any built-in square root function.

## Requirements

### Functional Requirements

1. Accept a non-negative integer as input
2. Find the largest integer r such that r * r <= n
3. Return r as a non-negative integer
4. Do not use any built-in square root or power functions

### Input Specification

- **n**: A non-negative integer (0 or greater)
- **Return**: A non-negative integer r such that r * r <= n < (r+1) * (r+1)

### Constraints

- Input range: 0 to 2,147,483,647 (standard 32-bit integer maximum)
- Result is always an integer (floor of the true square root)
- Do not use built-in sqrt, pow, or equivalent functions
- Time complexity: O(sqrt(n)) or better

## Examples

### Example 1: Perfect square

**Input**: 9
**Output**: 3
**Explanation**: 3 * 3 = 9 = n, so integer square root is 3

### Example 2: Non-perfect square

**Input**: 8
**Output**: 2
**Explanation**: 2 * 2 = 4 <= 8 < 9 = 3 * 3, so integer square root is 2

### Example 3: Zero

**Input**: 0
**Output**: 0
**Explanation**: 0 * 0 = 0 = n, so integer square root is 0

### Example 4: One

**Input**: 1
**Output**: 1
**Explanation**: 1 * 1 = 1 = n, so integer square root is 1

### Example 5: Large perfect square

**Input**: 100
**Output**: 10
**Explanation**: 10 * 10 = 100 = n

### Example 6: Large non-perfect square

**Input**: 15
**Output**: 3
**Explanation**: 3 * 3 = 9 <= 15 < 16 = 4 * 4, so result is 3

## Notes

Approaches: linear search from 0 upward (stop when r*r > n, return r-1), or binary search over the range [0, n] for better efficiency on large inputs.

Common mistakes:
- Returning r when r*r == n+1 (off-by-one in loop termination)
- Integer overflow when computing r*r for large r (use 64-bit arithmetic if needed)
- Returning a float instead of an integer
