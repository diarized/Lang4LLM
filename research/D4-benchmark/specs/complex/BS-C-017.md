# BS-C-017: Strategy Pattern — Swappable Sort

**Tier**: Complex
**Category**: Object-Oriented Design
**Estimated LOC**: 80-110

## Task Description

Implement a sorting system where the sorting algorithm (bubble sort, insertion sort, or merge sort) is represented as an interchangeable strategy object. A sorter container holds a reference to the current strategy and delegates all sorting to it. The strategy can be replaced at runtime. A timing wrapper measures the elapsed time of a sort operation and returns both the sorted result and the duration.

## Requirements

### Functional Requirements

1. Implement three sort strategy objects, each encapsulating a single sorting algorithm:
   - **Bubble Sort**: compare adjacent elements, swap if out of order, repeat until no swaps occur
   - **Insertion Sort**: build the sorted portion one element at a time by inserting each element into its correct position
   - **Merge Sort**: recursively split the list into halves, sort each half, and merge them back together in order
2. Implement a sorter container that holds a reference to the current strategy; provide a way to set or swap the strategy at any time
3. The container exposes a `sort(list)` operation that delegates to the currently assigned strategy and returns a sorted copy of the input list (original list must not be modified)
4. Implement a `timed_sort(sorter, list)` function that records the time before and after calling sort, and returns both the sorted list and the elapsed duration as a measurement value
5. All three strategies must produce identical sorted output for the same input
6. Strategies must sort in ascending order

### Input Specification

- **list**: A list of comparable values (numbers for testing); length 0 to 10,000
- **strategy**: One of the three sort strategy objects (bubble, insertion, or merge)
- **sorter**: A container object holding a current strategy reference
- **sort(list)** on sorter: Returns a new sorted list; input list unchanged
- **timed_sort(sorter, list)**: Returns a pair of (sorted list, duration); duration is a non-negative number representing elapsed time in any consistent unit

### Constraints

- The sorted output must be in non-decreasing (ascending) order
- The input list must not be modified by any sort operation
- All three strategy implementations must be independent (no shared sorting logic between them)
- Merge sort implementation must use a divide-and-conquer recursive approach
- No built-in sort functions from the standard library allowed in the strategy implementations
- timed_sort must wrap the actual sort call (not a re-implementation)

## Examples

### Example 1: Swapping strategies produce identical output

**Operations**:
```
list = [5, 2, 8, 1, 9, 3]
sorter = create_sorter()

set_strategy(sorter, bubble_sort_strategy())
result_bubble = sort(sorter, list)
// result_bubble = [1, 2, 3, 5, 8, 9]

set_strategy(sorter, merge_sort_strategy())
result_merge = sort(sorter, list)
// result_merge = [1, 2, 3, 5, 8, 9]

// result_bubble == result_merge
// list is unchanged: still [5, 2, 8, 1, 9, 3]
```

**Explanation**:
- Both strategies produce the same sorted output
- Swapping strategy does not affect the input list

### Example 2: Runtime strategy swap between sorts

**Operations**:
```
sorter = create_sorter()
data = [4, 2, 7, 1]

set_strategy(sorter, insertion_sort_strategy())
r1 = sort(sorter, data)
// r1 = [1, 2, 4, 7]

set_strategy(sorter, bubble_sort_strategy())
r2 = sort(sorter, data)
// r2 = [1, 2, 4, 7]

// Same output, different strategies were used
```

**Explanation**:
- Sorter delegates to whichever strategy is currently set
- Replacing strategy between calls requires no changes to calling code

### Example 3: Timed sort

**Operations**:
```
sorter = create_sorter()
set_strategy(sorter, merge_sort_strategy())

(result, elapsed) = timed_sort(sorter, [10, 5, 3, 8, 1])
// result = [1, 3, 5, 8, 10]
// elapsed >= 0  (a non-negative duration measurement)
```

**Explanation**:
- timed_sort returns both the sorted list and a duration
- Duration may be very small for short lists but must be non-negative

### Example 4: Edge cases — empty and single element

**Operations**:
```
sorter = create_sorter()
set_strategy(sorter, bubble_sort_strategy())

sort(sorter, [])     // returns []
sort(sorter, [42])   // returns [42]

set_strategy(sorter, merge_sort_strategy())
sort(sorter, [])     // returns []
sort(sorter, [42])   // returns [42]
```

**Explanation**:
- All strategies handle empty list and single-element list correctly

### Example 5: Already-sorted and reverse-sorted inputs

**Operations**:
```
sorter = create_sorter()
set_strategy(sorter, insertion_sort_strategy())

sort(sorter, [1, 2, 3, 4, 5])    // returns [1, 2, 3, 4, 5]
sort(sorter, [5, 4, 3, 2, 1])    // returns [1, 2, 3, 4, 5]
```

**Explanation**:
- Sorted input: no swaps needed (bubble/insertion best case)
- Reverse input: maximum work required (all strategies still correct)

## Notes

**Implementation Strategies**:

**Bubble Sort**:
- Outer loop runs until a complete pass produces no swaps
- Inner loop compares adjacent pairs and swaps if left > right
- Optimization: track whether any swap occurred; if not, list is sorted

**Insertion Sort**:
- Maintain a sorted prefix of the list
- For each new element, walk backward through the sorted prefix to find insertion point
- Shift elements right to make room; insert the element

**Merge Sort**:
- Base case: list of length 0 or 1 is already sorted
- Split list at midpoint into two halves
- Recursively sort each half
- Merge: consume from both sorted halves in order, picking the smaller element each time

**Strategy Container**:
- Stores a reference to the current strategy object
- sort() method simply calls the current strategy's sort logic
- Strategy replacement: assign new strategy reference

**Timing**:
- Record timestamp before calling sort, record timestamp after, compute difference
- Use the platform's highest-resolution available timer for accuracy

**Common Mistakes**:
- Modifying the input list in-place instead of returning a sorted copy
- Merge sort: merging back into the wrong buffer (off-by-one in merge indices)
- Bubble sort: not breaking early when no swaps occur (runs unnecessarily)
- Insertion sort: shifting in wrong direction or stopping shift at wrong condition
- Not implementing strategies as independent objects (coupling them together)
