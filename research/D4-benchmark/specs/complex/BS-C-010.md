# BS-C-010: Mathematical Expression Tokenizer

**Tier**: Complex
**Category**: String Processing
**Estimated LOC**: 80-120

## Task Description

Implement a tokenizer (lexer) that takes a mathematical expression string and produces a flat list of typed tokens. The tokenizer must correctly identify numbers (including multi-digit and decimal), arithmetic operators, parentheses, and handle leading whitespace and the distinction between unary negation and binary subtraction.

## Requirements

### Functional Requirements

1. Parse the input string from left to right and produce a list of tokens in the same order as they appear in the input
2. Recognize the following token types:
   - **NUMBER**: A sequence of digits optionally containing one decimal point (e.g., "3", "42", "3.14", "0.5"); numbers must start with a digit
   - **PLUS**: The character "+"
   - **MINUS**: The character "-" when it is a binary operator (follows a number or closing parenthesis)
   - **NEGATE**: The character "-" when it is a unary minus (follows an operator, an opening parenthesis, or appears at the start of the expression)
   - **MULTIPLY**: The character "*"
   - **DIVIDE**: The character "/"
   - **LPAREN**: The character "("
   - **RPAREN**: The character ")"
3. Whitespace (spaces and tabs) is skipped and does not produce tokens
4. Produce an error signal (raise an exception, return an error code, or return an error token) for any character not in the set {0-9, ".", "+", "-", "*", "/", "(", ")", space, tab}
5. A decimal point without surrounding digits (e.g., ".5", "3.", ".") produces an error
6. The token list preserves the original left-to-right order of the expression

### Input Specification

- **expression**: A string — the mathematical expression to tokenize; length 0 to 1,000 characters
- **Return**: A list of token objects or pairs, each containing:
  - A token type (from the set described above)
  - The token value: the numeric string for NUMBER tokens, the operator character for operator tokens, the parenthesis character for parenthesis tokens

### Constraints

- Input length: 0 to 1,000 characters
- Numbers may have at most one decimal point
- Negative numbers are represented as a NEGATE token followed by a NUMBER token (not as a single token with a leading minus)
- No multi-character operators (no "**", "//", "<=")
- Whitespace is only space (ASCII 32) and tab (ASCII 9)

## Examples

### Example 1: Simple arithmetic

**Input**: "3 + 4 * 2"

**Output**:
```
[NUMBER "3", PLUS "+", NUMBER "4", MULTIPLY "*", NUMBER "2"]
```

**Explanation**: Whitespace is skipped. All tokens are in left-to-right order.

### Example 2: Decimal number

**Input**: "3.14 * 2"

**Output**:
```
[NUMBER "3.14", MULTIPLY "*", NUMBER "2"]
```

**Explanation**: "3.14" is one NUMBER token. The decimal point is part of the number.

### Example 3: Unary negation vs binary subtraction

**Input**: "-3 + 5 - 2"

**Output**:
```
[NEGATE "-", NUMBER "3", PLUS "+", NUMBER "5", MINUS "-", NUMBER "2"]
```

**Explanation**:
- The first "-" is at the start of the expression, so it is NEGATE (unary)
- The second "-" follows a NUMBER token, so it is MINUS (binary)

### Example 4: Negation after operators and parentheses

**Input**: "(-3 + -4) * -(5)"

**Output**:
```
[LPAREN "(", NEGATE "-", NUMBER "3", PLUS "+", NEGATE "-", NUMBER "4", RPAREN ")",
 MULTIPLY "*", NEGATE "-", LPAREN "(", NUMBER "5", RPAREN ")"]
```

**Explanation**:
- "-" after "(" is NEGATE
- "-" after "+" is NEGATE
- "-" after "*" is NEGATE

### Example 5: Nested parentheses

**Input**: "((1 + 2)) / 3"

**Output**:
```
[LPAREN "(", LPAREN "(", NUMBER "1", PLUS "+", NUMBER "2", RPAREN ")", RPAREN ")", DIVIDE "/", NUMBER "3"]
```

### Example 6: Error cases

**Input**: "3 @ 4"
**Output**: error (unknown character "@")

**Input**: ".5 + 2"
**Output**: error (number starts with decimal point, not a digit)

**Input**: "3. + 2"
**Output**: error (number ends with decimal point, no digit after it)

**Input**: ""
**Output**: [] (empty input produces empty token list)

## Notes

**Implementation Strategy — Character-by-Character Scan**:
- Maintain a current position (index) in the expression string
- At each position, skip whitespace characters
- Inspect the current character to determine the token type:
  - Digit: begin collecting a NUMBER token; continue consuming digits and at most one decimal point
  - "+": emit PLUS
  - "-": determine MINUS vs NEGATE based on the last emitted token type (see rule below)
  - "*": emit MULTIPLY
  - "/": emit DIVIDE
  - "(": emit LPAREN
  - ")": emit RPAREN
  - Any other character: emit error

**Unary vs Binary Minus Rule**:
- If no tokens have been emitted yet (start of expression): emit NEGATE
- If the last emitted token was NUMBER or RPAREN: emit MINUS (binary)
- If the last emitted token was PLUS, MINUS, MULTIPLY, DIVIDE, NEGATE, or LPAREN: emit NEGATE (unary)

**Number Collection**:
- Consume digits until a non-digit is found
- If the current character is a decimal point and no decimal point has been consumed yet, consume it and continue consuming digits
- If no digits follow the decimal point, or no digits precede it, produce an error
- Produce a single NUMBER token with the full numeric string as its value

**Common Mistakes**:
- Treating unary minus as part of the number token (produces "-3" as one NUMBER instead of NEGATE + NUMBER "3"); this breaks downstream parsers
- Classifying the second "-" in "5 - -3" as binary subtraction (it follows MINUS which should produce NEGATE)
- Greedily consuming a decimal point as part of a number when it is actually a standalone character ("3." where "." is the last character)
- Not tracking the last-emitted token type, making NEGATE/MINUS disambiguation impossible
- Emitting whitespace as tokens instead of skipping them
- Missing the case where NEGATE appears after NEGATE (e.g., "--3" is valid: NEGATE, NEGATE, NUMBER)
