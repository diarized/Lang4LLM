# BS-C-018: Command Pattern

**Tier**: Complex
**Category**: Object-Oriented Design
**Estimated LOC**: 80-110

## Task Description

Implement a command processor that manages executable command objects supporting undo and redo. Each command encapsulates a reversible operation with distinct execute and undo actions. The processor maintains a history of executed commands and a redo stack, enabling arbitrary undo and redo sequences up to a configurable maximum history depth.

## Requirements

### Functional Requirements

1. Support creating individual command objects; each command has two operations: an execute action (do) and an undo action (reverse)
2. Implement a command processor with a bounded history of at most N executed commands (N specified at processor creation)
3. Support `execute(processor, command)` that runs the command's execute action, adds the command to the history, and clears the redo stack
4. Support `undo(processor)` that reverses the most recent command (calls its undo action), removes it from history, and pushes it onto the redo stack; if history is empty, do nothing
5. Support `redo(processor)` that re-executes the most recent undone command (calls its execute action), removes it from the redo stack, and returns it to history; if redo stack is empty, do nothing
6. When the history reaches maximum depth N and a new command is executed, the oldest command is dropped from history (it can no longer be undone via this processor)
7. Executing a new command always clears the redo stack entirely
8. The processor must expose the current history size and redo stack size for inspection

### Input Specification

- **N (max history)**: A positive integer (1 to 1,000) — maximum commands retained in history
- **command**: An object with:
  - An execute operation (no arguments, performs the command's action, returns nothing)
  - An undo operation (no arguments, reverses the command's action, returns nothing)
- **execute(processor, command)**: Runs command, adds to history, clears redo stack
- **undo(processor)**: Reverses last command, moves it to redo stack
- **redo(processor)**: Re-executes last undone command, moves it back to history
- **history_size(processor)**: Returns number of commands in history
- **redo_size(processor)**: Returns number of commands available for redo

### Constraints

- History is bounded by N; oldest commands are silently dropped when the bound is exceeded
- Undo on empty history: no-op (no error)
- Redo on empty redo stack: no-op (no error)
- Commands must not share mutable state in a way that breaks undo/redo ordering
- No external command/event sourcing libraries allowed

## Examples

### Example 1: Basic execute and undo

**Operations**:
```
value = 0
cmd_add = command(
  execute: function() { value = value + 10 },
  undo:    function() { value = value - 10 }
)

processor = create_processor(max_history=10)
execute(processor, cmd_add)
// value = 10, history_size = 1, redo_size = 0

undo(processor)
// value = 0, history_size = 0, redo_size = 1

redo(processor)
// value = 10, history_size = 1, redo_size = 0
```

**Explanation**:
- execute runs the action and adds to history
- undo reverses action and moves command to redo stack
- redo re-runs the action and moves command back to history

### Example 2: Redo stack cleared on new execute

**Operations**:
```
value = 0
cmd_a = command(execute: { value += 1 }, undo: { value -= 1 })
cmd_b = command(execute: { value += 5 }, undo: { value -= 5 })

processor = create_processor(max_history=10)
execute(processor, cmd_a)   // value = 1
execute(processor, cmd_a)   // value = 2
undo(processor)             // value = 1, redo_size = 1
execute(processor, cmd_b)   // value = 6, redo_size = 0 (cleared)
redo(processor)             // no-op: redo stack is empty
// value = 6
```

**Explanation**:
- Executing a new command after undo clears the redo stack
- redo after redo stack is cleared does nothing

### Example 3: History depth limit

**Operations**:
```
values = []
processor = create_processor(max_history=3)

for i in 1..5:
  cmd = command(execute: { values.append(i) }, undo: { values.pop() })
  execute(processor, cmd)

// history_size = 3  (oldest two commands dropped)
// values = [1, 2, 3, 4, 5]

undo(processor)  // undoes cmd 5, values = [1, 2, 3, 4]
undo(processor)  // undoes cmd 4, values = [1, 2, 3]
undo(processor)  // undoes cmd 3, values = [1, 2]
undo(processor)  // no-op: history empty (cmd 1 and 2 were dropped)
// values = [1, 2]  (cmd 1 and 2 cannot be undone)
```

**Explanation**:
- With max_history=3, only the 3 most recent commands are retained
- Commands that fall off the history boundary cannot be undone

### Example 4: Multi-step undo and redo sequence

**Operations**:
```
counter = 0
make_cmd = function(n) {
  return command(execute: { counter += n }, undo: { counter -= n })
}

processor = create_processor(max_history=10)
execute(processor, make_cmd(1))   // counter = 1
execute(processor, make_cmd(2))   // counter = 3
execute(processor, make_cmd(3))   // counter = 6

undo(processor)   // counter = 3
undo(processor)   // counter = 1
redo(processor)   // counter = 3
redo(processor)   // counter = 6
redo(processor)   // no-op: redo stack empty
// counter = 6
```

**Explanation**:
- Multiple undos then redos restore state correctly
- redo past the end of the redo stack does nothing

## Test Cases

### Required Coverage

1. Execute one command; verify action runs and history size is 1
2. Undo one command; verify undo action runs, history size is 0, redo size is 1
3. Redo one command; verify execute action runs again, history size is 1, redo size is 0
4. Undo on empty history is a no-op (no error)
5. Redo on empty redo stack is a no-op (no error)
6. Execute after undo clears redo stack
7. Multiple undos then multiple redos restore correct state
8. History depth limit: execute N+1 commands, verify oldest cannot be undone
9. History depth of 1: every new execute drops previous command
10. Verify history_size and redo_size counts are accurate at each step
11. Undo, redo, undo sequence (alternating) produces correct state
12. Execute two different commands, undo both, redo both — correct order

### Minimum Test Count

12 test cases

## Success Criteria

- [ ] Execute runs the command's action and adds it to history
- [ ] Undo reverses the most recent command and moves it to redo stack
- [ ] Redo re-executes the most recent undone command and restores it to history
- [ ] Executing a new command clears the redo stack entirely
- [ ] History depth limit is enforced; oldest commands are dropped first
- [ ] Undo on empty history and redo on empty redo stack are safe no-ops
- [ ] history_size and redo_size accurately reflect current state

## Notes

**Implementation Strategies**:

**History as bounded stack**:
- Use a double-ended queue (deque) or a bounded circular buffer
- On execute: push new command onto the front (most recent end)
- If history size exceeds N after push: remove from the back (oldest end)
- On undo: pop from front, push onto redo stack
- On redo: pop from redo stack, push onto history front

**Redo stack**:
- An unbounded stack (in practice bounded by the depth of undo operations)
- Cleared completely when a new execute occurs

**Command Object Design**:
- Each command stores references to its execute and undo callables
- Commands should be self-contained and not depend on execution order for correctness
- If commands capture state (e.g., "old value" for undo), capture it at execute time, not at command creation time, for commands that depend on current state

**Common Mistakes**:
- Forgetting to clear the redo stack when execute is called
- Removing the wrong end of the history when enforcing the depth limit (remove oldest, not newest)
- Undoing in wrong order (undoing oldest instead of most recent)
- Redo using the wrong end of the redo stack (redo should undo the most-recently-undone command)
- Off-by-one: allowing history_size to grow to N+1 before trimming

**Edge Cases**:
- max_history = 1 (only the single most recent command can be undone)
- All commands undone, then redo all of them back
- Long undo chain followed by a single execute (which wipes the entire redo stack)
