# BS-C-014: Report Generator

**Tier**: Complex
**Category**: File I/O
**Estimated LOC**: 70-100

## Task Description

Implement a report generator that accepts a list of records (each with a name and a list of numeric scores), and produces a formatted plain-text tabular report with a header row, one data row per record, a totals/summary row at the bottom, and columns aligned so that all entries in each column are right- or left-aligned consistently.

## Requirements

### Functional Requirements

1. Accept a list of records, each containing a name (text) and a list of scores (numbers)
2. Generate a plain-text report with the following structure:
   - A title line at the top
   - A horizontal separator line
   - A header row with column names: "Name", "Score 1", "Score 2", ... (one column per score)
   - A separator line below the header
   - One data row per record showing the name and each score
   - A separator line above the summary row
   - A summary row labeled "TOTAL" showing the sum of each score column across all records
   - A closing separator line
3. Align all columns: the Name column is left-aligned, all score columns are right-aligned
4. Each column width is determined by the widest entry in that column (including the header label)
5. Columns are separated by a vertical bar character with one space of padding on each side
6. Separator lines use dashes that span the full width of the table
7. Return the complete report as a single text string (or write to a provided output destination)

### Input Specification

- **title**: A text string for the report heading
- **records**: A list of record objects, each containing:
  - **name**: A text string (the record identifier)
  - **scores**: A list of numbers (equal length across all records)
- **Return**: A text string containing the complete formatted report

### Constraints

- All records must have the same number of scores
- At least one record must be present
- Score values are real numbers; display with at most 2 decimal places
- Name column: up to 50 characters
- Number of score columns: 1 to 10
- Minimum column width: determined by header label width

## Examples

### Example 1: Simple 2-record, 2-score report

**Input**:
```
title = "Student Scores"
records = [
  {name: "Alice", scores: [85, 92]},
  {name: "Bob",   scores: [78, 88]}
]
```

**Output**:
```
Student Scores
---------------------------------
Name  | Score 1 | Score 2
---------------------------------
Alice |      85 |      92
Bob   |      78 |      88
---------------------------------
TOTAL |     163 |     180
---------------------------------
```

**Explanation**:
- Name column is left-aligned and wide enough for "Alice"
- Score columns are right-aligned within column width
- TOTAL row sums each score column independently

### Example 2: Column widths driven by data

**Input**:
```
title = "Sales Report"
records = [
  {name: "Northern Region", scores: [12500.50, 8300.00]},
  {name: "South",           scores: [999.99,   10000.00]}
]
```

**Output**:
```
Sales Report
----------------------------------------------
Name             | Score 1   | Score 2
----------------------------------------------
Northern Region  |  12500.50 |   8300.00
South            |    999.99 |  10000.00
----------------------------------------------
TOTAL            |  13500.49 |  18300.00
----------------------------------------------
```

**Explanation**:
- Name column width = max(len("Name"), len("Northern Region"), len("South"), len("TOTAL")) = 15
- Score column widths accommodate formatted numbers
- Decimal values displayed with 2 decimal places

### Example 3: Single record and single score column

**Input**:
```
title = "Q1 Results"
records = [
  {name: "Team A", scores: [42]}
]
```

**Output**:
```
Q1 Results
------------------
Name   | Score 1
------------------
Team A |      42
------------------
TOTAL  |      42
------------------
```

**Explanation**:
- With one record, TOTAL equals that record's score
- Separator spans full table width including all columns

## Test Cases

### Required Coverage

1. Two records, two score columns (basic case)
2. Three or more records with varying name lengths
3. Score column width driven by a score value wider than the header label
4. Name column width driven by a record name wider than "TOTAL"
5. Name column width driven by "TOTAL" label (when all names are short)
6. Single record (TOTAL equals the record)
7. Single score column
8. Maximum score columns (at least 5 columns)
9. Scores with decimal values (verify 2-decimal formatting)
10. All separator lines span full table width (consistent length)
11. Column alignment: names left-aligned, scores right-aligned
12. TOTAL row sums correctly when scores include decimals
13. Report returned as a single text string with newlines

### Minimum Test Count

12 test cases

## Success Criteria

- [ ] Header, data rows, and totals row are all present and correctly populated
- [ ] Column widths are determined by the widest content in each column
- [ ] Name column is left-aligned; all score columns are right-aligned
- [ ] All separator lines have identical length equal to the full table width
- [ ] TOTAL row contains correct column sums
- [ ] Decimal scores formatted with at most 2 decimal places
- [ ] Output is a single string that renders as a readable plain-text table

## Notes

**Implementation Strategies**:

- Two-pass approach: first pass computes column widths, second pass formats rows
- Column width for column i = max(len(header_i), max over records of len(formatted_score_i), len(total_i))
- Name column width = max(len("Name"), max over records of len(name), len("TOTAL"))
- Format each row using the computed widths and alignment flags
- Separator line: dashes repeated to match total width (sum of column widths + separator characters)
- Total width formula: sum(col_widths) + number_of_columns * 3 - 1 (for " | " separators)

**Column Formatting**:
- Left-align: pad with spaces on the right
- Right-align: pad with spaces on the left
- Use consistent formatting for numbers (e.g., always show decimals, or omit when whole number — choose and apply consistently)

**Common Mistakes**:
- Forgetting to account for separator characters (" | ") in total table width
- Computing column widths without including the TOTAL row values
- Misaligning columns when a score number is wider than the header label
- Separator lines that are too short or too long (off-by-one in width calculation)
- Not handling the case where "TOTAL" is the widest name-column entry

**Edge Cases**:
- All scores are zero (TOTAL row shows zeros, not empty)
- Record names shorter than "Name" (header determines minimum width)
- Score formatting: integer-valued scores should still render consistently with decimal scores in the same column
