# BS-C-005: Trie (Prefix Tree)

**Tier**: Complex
**Category**: Data Structures
**Estimated LOC**: 70-110

## Task Description

Implement a Trie (prefix tree) that stores strings character by character, supporting word insertion, exact-word lookup, prefix existence check, and retrieval of all words that share a given prefix. Each node in the trie represents a single character, and a special marker distinguishes complete words from partial paths.

## Requirements

### Functional Requirements

1. Support `insert(word)` to add a word to the trie; inserting an already-present word has no effect
2. Support `search(word)` returning true if the exact word was previously inserted, false otherwise; a prefix that is not itself a full word returns false
3. Support `starts_with(prefix)` returning true if any inserted word begins with the given prefix, false otherwise; an empty prefix always returns true
4. Support `words_with_prefix(prefix)` returning a list of all inserted words that begin with the given prefix; if no words match, return an empty list; if the prefix is empty, return all words; order within the returned list is not required to be sorted
5. All operations are case-sensitive

### Input Specification

- **insert(word)**: A non-empty string of lowercase letters — adds the word to the trie; returns nothing
- **search(word)**: A string — returns true if the exact word is stored, false otherwise
- **starts_with(prefix)**: A string (may be empty) — returns true if any stored word begins with this prefix
- **words_with_prefix(prefix)**: A string (may be empty) — returns a list of all stored words sharing this prefix; list may be in any order

### Constraints

- Words and prefixes consist of lowercase ASCII letters only (a-z)
- Word length: 1 to 100 characters
- Total number of words inserted: 0 to 10,000
- No built-in trie, prefix-tree, or sorted-map data structures allowed
- Time complexity: O(L) for insert, search, starts_with where L is string length; O(L + W) for words_with_prefix where W is total length of matching words

## Examples

### Example 1: Basic insert and search

**Operations**:
```
trie = Trie()
trie.insert("apple")
trie.insert("app")
trie.insert("application")
trie.search("app")          // returns true
trie.search("ap")           // returns false (not a full word)
trie.search("apple")        // returns true
trie.search("apricot")      // returns false (not inserted)
```

**Explanation**:
- "app" and "apple" are distinct words; both must be tracked simultaneously
- "ap" shares a prefix path but was never marked as a complete word

### Example 2: starts_with prefix check

**Operations**:
```
trie = Trie()
trie.insert("hello")
trie.insert("help")
trie.insert("world")
trie.starts_with("hel")    // returns true  (hello, help start with hel)
trie.starts_with("wor")    // returns true  (world starts with wor)
trie.starts_with("xyz")    // returns false (no word starts with xyz)
trie.starts_with("")       // returns true  (empty prefix matches all)
```

**Explanation**:
- starts_with checks for path existence in the trie, not for a complete word
- Empty prefix is a trivially valid prefix of any string

### Example 3: words_with_prefix retrieval

**Operations**:
```
trie = Trie()
trie.insert("car")
trie.insert("card")
trie.insert("care")
trie.insert("careful")
trie.insert("bat")
trie.words_with_prefix("car")   // returns ["car", "card", "care", "careful"] (any order)
trie.words_with_prefix("care")  // returns ["care", "careful"] (any order)
trie.words_with_prefix("cat")   // returns []
trie.words_with_prefix("")      // returns ["car", "card", "care", "careful", "bat"] (any order)
```

**Explanation**:
- words_with_prefix must collect all words reachable from the prefix node, including the prefix itself if it is a complete word
- Empty prefix traverses the entire trie

### Example 4: Duplicate insertion

**Operations**:
```
trie = Trie()
trie.insert("test")
trie.insert("test")
trie.words_with_prefix("test")  // returns ["test"] (not ["test", "test"])
```

**Explanation**:
- Inserting a word that already exists does not create a duplicate

## Test Cases

### Required Coverage

1. Insert a single word, search returns true for that word
2. Search for word that was never inserted returns false
3. Search for a valid prefix of an inserted word returns false (prefix is not a word)
4. Insert multiple words sharing a prefix, all are individually searchable
5. starts_with on a prefix shared by multiple words
6. starts_with on a prefix that matches no word
7. starts_with with empty prefix returns true
8. starts_with on an empty trie returns false (non-empty prefix) or true (empty prefix)
9. words_with_prefix returns all matching words
10. words_with_prefix with a prefix equal to an exact word includes that word in the result
11. words_with_prefix with empty prefix returns all inserted words
12. words_with_prefix for non-matching prefix returns empty list
13. Duplicate word insertion does not create duplicate in words_with_prefix results
14. All operations on empty trie return correct results
15. Insert word then search after inserting many other words

### Minimum Test Count

15 test cases

## Success Criteria

- [ ] Exact word search correctly distinguishes complete words from prefixes
- [ ] starts_with correctly identifies any matching word for a given prefix
- [ ] words_with_prefix returns all and only words that begin with the prefix
- [ ] Empty prefix is handled correctly in starts_with and words_with_prefix
- [ ] Duplicate insertions do not produce duplicate entries
- [ ] All operations are correct on an empty trie
- [ ] Word and prefix sharing characters do not interfere with each other's end-of-word markers

## Notes

**Implementation Strategy**:
- Each node contains a mapping from character to child node, plus a boolean flag indicating whether this node is the end of a complete word
- Insert: traverse the trie character by character, creating new nodes as needed; mark the final node as a word end
- Search: traverse the trie character by character; return true only if all characters are found AND the final node is marked as a word end
- starts_with: same traversal as search but do not check the word-end marker
- words_with_prefix: traverse to the node corresponding to the last character of the prefix; then perform a depth-first (or breadth-first) traversal of all reachable nodes, collecting words at every word-end node

**Collecting words_with_prefix**:
- Maintain the current string being built during DFS/BFS
- When a word-end node is reached, record the accumulated string as a result
- Backtrack the current string after exploring each child (for recursive DFS)

**Common Mistakes**:
- Returning true from search when the traversal ends mid-word but node has a word-end marker from a shorter insert (mixing up which node you are at)
- Not including the prefix itself in words_with_prefix results when the prefix is a complete word
- Forgetting to handle the empty prefix in words_with_prefix (should traverse from root)
- Modifying the shared character-to-child mapping during DFS collection (causes incomplete results)
- Losing the accumulated word string due to incorrect string concatenation or mutation

**Edge Cases**:
- Empty trie for all operations
- One-character words ("a", "b")
- A word that is a prefix of another word ("app" vs "apple")
- Prefix equal to the full word (words_with_prefix("apple") with only "apple" inserted)
- Very long words (100 characters)
