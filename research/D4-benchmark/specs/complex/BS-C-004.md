# BS-C-004: Binary Search Tree

**Tier**: Complex
**Category**: Data Structures
**Estimated LOC**: 80-120

## Task Description

Implement a Binary Search Tree (BST) that supports insertion, search, deletion, and in-order traversal. Duplicate values are rejected silently (the tree does not store them). Deletion must handle all three structural cases: removing a leaf, a node with one child, and a node with two children.

## Requirements

### Functional Requirements

1. Support `insert(value)` to add a value into the tree; if the value already exists, do nothing
2. Support `search(value)` returning true if the value exists in the tree, false otherwise
3. Support `delete(value)` to remove a value from the tree; if the value does not exist, do nothing
4. Support `inorder()` returning the values of the tree as a list in ascending sorted order
5. Maintain the BST invariant after every operation: all values in a node's left subtree are strictly less than the node's value, and all values in the right subtree are strictly greater
6. Deletion of a node with two children must replace the node with its in-order successor (smallest value in the right subtree)

### Input Specification

- **insert(value)**: An integer — adds it to the tree if not already present; returns nothing
- **search(value)**: An integer — returns true if present, false otherwise
- **delete(value)**: An integer — removes it from the tree if present; returns nothing
- **inorder()**: No parameters — returns a list of integers in ascending order; returns empty list for empty tree

### Constraints

- Values are integers in the range -100,000 to 100,000
- Tree may hold 0 to 10,000 values
- No built-in tree or sorted-set data structures allowed
- Time complexity: O(h) for insert, search, delete where h is tree height; O(n) for inorder
- Duplicates must be silently rejected (no error, no modification)

## Examples

### Example 1: Basic insert and inorder

**Operations**:
```
bst = BST()
bst.insert(5)
bst.insert(3)
bst.insert(7)
bst.insert(1)
bst.insert(4)
bst.inorder()   // returns [1, 3, 4, 5, 7]
```

**Explanation**:
- Tree shape after inserts: 5 is root, 3 is left child, 7 is right child, 1 and 4 are children of 3
- Inorder traversal visits left subtree, root, right subtree — yielding sorted order

### Example 2: Search

**Operations**:
```
bst = BST()
bst.insert(10)
bst.insert(6)
bst.insert(14)
bst.search(6)   // returns true
bst.search(9)   // returns false
bst.search(10)  // returns true
```

**Explanation**:
- 6 and 10 were inserted, so both return true
- 9 was never inserted, so search returns false

### Example 3: Duplicate rejection

**Operations**:
```
bst = BST()
bst.insert(5)
bst.insert(5)
bst.insert(5)
bst.inorder()   // returns [5]
```

**Explanation**:
- Subsequent inserts of 5 are silently ignored
- Tree contains exactly one node

### Example 4: Deletion — all three cases

**Operations**:
```
bst = BST()
bst.insert(8)
bst.insert(4)
bst.insert(12)
bst.insert(2)
bst.insert(6)
bst.insert(10)
bst.insert(14)

// Case 1: delete leaf
bst.delete(2)
bst.inorder()   // returns [4, 6, 8, 10, 12, 14]

// Case 2: delete node with one child (6 has no right child if 5 not inserted)
bst.insert(5)
bst.delete(6)
bst.inorder()   // returns [4, 5, 8, 10, 12, 14]

// Case 3: delete node with two children
bst.delete(12)
// in-order successor of 12 is 14; 14 replaces 12
bst.inorder()   // returns [4, 5, 8, 10, 14]
```

**Explanation**:
- Leaf deletion removes the node directly
- One-child deletion replaces the node with its sole child
- Two-children deletion finds the smallest value in the right subtree (in-order successor) and places it at the deleted node's position

### Example 5: Delete non-existent value

**Operations**:
```
bst = BST()
bst.insert(3)
bst.delete(99)  // no effect
bst.inorder()   // returns [3]
```

**Explanation**:
- Deleting a value not in the tree leaves the tree unchanged

## Notes

**Implementation Strategy**:
- Represent the tree using nodes, each holding a value and references to left and right children
- Maintain a reference to the root node; root is null/none for an empty tree
- All four operations are naturally recursive: recurse left if target is less than current node value, right if greater, act at current node if equal

**Deletion — In-Order Successor**:
- When deleting a node with two children, find the minimum value in the right subtree (go right once, then left as far as possible)
- Copy that successor's value into the current node
- Then delete the successor from the right subtree (it has at most one child — a right child — so this is a simpler case)

**Common Mistakes**:
- Forgetting to return the modified subtree root in recursive implementations (the link from parent is not updated)
- Handling deletion of the root node as a special case when the general recursive approach already covers it
- Confusing in-order successor with in-order predecessor (spec requires successor)
- Not handling the one-child case for both left-only and right-only child
- Off-by-one or missed null checks causing crashes on empty subtrees

**Edge Cases**:
- Empty tree for every operation
- Tree with a single node (delete it, search it, insert into it)
- Fully left-skewed or right-skewed tree (all inserts in sorted order)
- Deleting a node that is the direct parent of the in-order successor
