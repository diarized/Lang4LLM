# BS-C-003: Expression Parser and Evaluator

**Tier**: Complex
**Category**: Algorithms / String Processing
**Estimated LOC**: 100-150

## Task Description

Parse and evaluate mathematical expressions containing numbers, operators (+, -, *, /), and parentheses, respecting operator precedence and associativity.

## Requirements

### Functional Requirements

1. Accept a string containing a mathematical expression
2. Parse the expression into an evaluatable form
3. Evaluate the expression and return the result
4. Support operators: +, -, *, / (addition, subtraction, multiplication, division)
5. Support parentheses for grouping: ( )
6. Respect operator precedence: * and / before + and -
7. Support negative numbers
8. Handle whitespace (spaces should be ignored)

### Input Specification

- **expression**: A string containing mathematical expression
  - Valid characters: digits (0-9), operators (+, -, *, /), parentheses ( ), spaces
  - Numbers can be integers or decimals (with decimal point)
- **Return**: Numeric result of evaluation (float/double)

### Constraints

- Expression length: 1 to 1,000 characters
- Numbers range: -1,000,000 to 1,000,000
- No division by zero (should return error or special value)
- No invalid expressions (assume input is well-formed for basic tests)
- Precision: floating-point arithmetic (standard language precision)

## Examples

### Example 1: Simple addition

**Input**: "3 + 5"
**Output**: 8.0
**Explanation**: Basic addition

### Example 2: Operator precedence

**Input**: "2 + 3 * 4"
**Output**: 14.0
**Explanation**: Multiplication before addition: 2 + (3 * 4) = 2 + 12 = 14

### Example 3: Parentheses

**Input**: "(2 + 3) * 4"
**Output**: 20.0
**Explanation**: Parentheses override precedence: (2 + 3) * 4 = 5 * 4 = 20

### Example 4: Nested parentheses

**Input**: "((2 + 3) * 4) + 10"
**Output**: 30.0
**Explanation**: Innermost first: (2+3)=5, 5*4=20, 20+10=30

### Example 5: Division

**Input**: "10 / 2 + 3"
**Output**: 8.0
**Explanation**: Division before addition: (10 / 2) + 3 = 5 + 3 = 8

### Example 6: Complex expression

**Input**: "2 * (3 + 4) - 10 / 5"
**Output**: 12.0
**Explanation**: 2*(3+4) = 2*7 = 14, 10/5 = 2, 14-2 = 12

### Example 7: Negative numbers

**Input**: "-5 + 3"
**Output**: -2.0
**Explanation**: Negative number at start

### Example 8: Decimal numbers

**Input**: "3.5 * 2"
**Output**: 7.0
**Explanation**: Decimal multiplication

### Example 9: Multiple operations same precedence

**Input**: "10 - 3 - 2"
**Output**: 5.0
**Explanation**: Left-to-right: (10 - 3) - 2 = 7 - 2 = 5

### Example 10: With whitespace

**Input**: "  3  +  5  "
**Output**: 8.0
**Explanation**: Whitespace ignored

## Notes

**Implementation Approach 1: Recursive Descent Parser**

Grammar:
```
expression  := term (('+' | '-') term)*
term        := factor (('*' | '/') factor)*
factor      := number | '(' expression ')'
number      := ['-'] digit+ ['.' digit+]
```

Parse recursively following grammar structure.

**Implementation Approach 2: Shunting Yard Algorithm**

Convert infix notation to postfix (RPN), then evaluate:
1. Use stack for operators and output queue for numbers
2. Process tokens left to right:
   - Number: add to output
   - Operator: pop higher/equal precedence operators from stack to output, then push operator
   - '(': push to stack
   - ')': pop until '(', add operators to output
3. Pop remaining operators to output
4. Evaluate postfix expression using stack

**Operator Precedence** (high to low):
1. Parentheses: ()
2. Multiplication, Division: *, /
3. Addition, Subtraction: +, -

**Operator Associativity**:
- All operators: left-to-right
- Example: 10 - 3 - 2 = (10 - 3) - 2 = 5

**Common Mistakes**:
- Incorrect operator precedence (+ before *)
- Right-to-left associativity instead of left-to-right
- Not handling negative numbers at expression start
- Not handling nested parentheses
- Not ignoring whitespace
- Integer division instead of floating-point
- Not handling decimal points
- Stack overflow with deeply nested parentheses
- Not validating parentheses matching

**Edge Cases**:
- Single number: "42" -> 42.0
- Negative number: "-5" -> -5.0
- Expression with leading/trailing spaces
- Nested parentheses: "(((3)))" -> 3.0
- Consecutive operations: "2 + 3 + 4" -> 9.0
- Zero in expressions: "0 + 5" -> 5.0

**Error Handling** (optional advanced):
- Division by zero: "5 / 0" -> error or infinity
- Unmatched parentheses: "(3 + 5" -> error
- Invalid characters: "3 & 5" -> error
- Empty expression: "" -> error

**Testing Strategy**:
1. Test each operator independently
2. Test operator precedence pairs
3. Test parentheses at different nesting levels
4. Test edge cases (single number, negative, decimal)
5. Test complex expressions combining all features
6. Compare results with calculator or eval() function

**Debugging Tips**:
- Print parsed tokens

- Use small expressions first, then build complexity
