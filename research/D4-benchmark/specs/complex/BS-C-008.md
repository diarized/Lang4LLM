# BS-C-008: Merge Sort with Inversion Count

**Tier**: Complex
**Category**: Algorithms
**Estimated LOC**: 60-90

## Task Description

Implement recursive merge sort that sorts a list of integers in ascending order and simultaneously counts the number of inversions in the original list. An inversion is a pair of indices (i, j) where i < j but the element at i is greater than the element at j. Return both the sorted list and the inversion count.

## Requirements

### Functional Requirements

1. Accept a list of integers and sort it in ascending order using the merge sort algorithm
2. Count the total number of inversions in the original list; an inversion is defined as a pair (i, j) with i < j and list[i] > list[j]
3. Return both the sorted list and the inversion count as a pair or two separate values
4. The sort must be implemented recursively by dividing the list into two halves, sorting each half, and merging the sorted halves
5. Count inversions during the merge step, not by a separate brute-force scan: when an element from the right half is placed before elements remaining in the left half, it forms inversions with all remaining left-half elements
6. The original list must not be modified in place; the sorted output is a new list (or the return value); the inversion count reflects the original list's order

### Input Specification

- **list**: A list of integers — may contain duplicates; length 0 to 100,000
- **Return**: A pair consisting of:
  - A new list of integers sorted in ascending order
  - A non-negative integer representing the number of inversions in the original input list

### Constraints

- List length: 0 to 100,000 elements
- Integer values: -1,000,000 to 1,000,000
- Duplicates allowed; equal elements (list[i] == list[j] with i < j) are NOT counted as inversions
- Inversion count may be large (up to approximately n*(n-1)/2 for a fully reversed list)
- Time complexity: O(n log n) — brute-force O(n²) inversion counting is not acceptable
- Space complexity: O(n) additional space for merge step

## Examples

### Example 1: Basic sort and inversion count

**Input**: [3, 1, 2]
**Output**: sorted = [1, 2, 3], inversions = 2

**Explanation**:
- Inversions: (3,1) at indices (0,1) and (3,2) at indices (0,2) — total 2
- Pair (1,2) at indices (1,2) is not an inversion because 1 < 2

### Example 2: Already sorted list

**Input**: [1, 2, 3, 4, 5]
**Output**: sorted = [1, 2, 3, 4, 5], inversions = 0

**Explanation**:
- No pair (i,j) with i < j has list[i] > list[j]

### Example 3: Reverse sorted list (maximum inversions)

**Input**: [4, 3, 2, 1]
**Output**: sorted = [1, 2, 3, 4], inversions = 6

**Explanation**:
- All 4*(4-1)/2 = 6 pairs are inversions: (4,3),(4,2),(4,1),(3,2),(3,1),(2,1)

### Example 4: List with duplicates

**Input**: [2, 1, 2, 1]
**Output**: sorted = [1, 1, 2, 2], inversions = 4

**Explanation**:
- Inversions: (2,1) at (0,1), (2,1) at (0,3), (2,1) at (2,3), and the 2 at index 2 vs 1 at index 3
- Pairs with equal values — (2,2) at indices (0,2) and (1,1) at indices (1,3) — are not inversions
- Count: index pairs (0,1), (0,3), (2,3), and (0 vs 3 through position 2): verify carefully
  - (i=0, j=1): list[0]=2 > list[1]=1 → inversion
  - (i=0, j=3): list[0]=2 > list[3]=1 → inversion
  - (i=2, j=3): list[2]=2 > list[3]=1 → inversion
  - (i=1, j=2): list[1]=1 < list[2]=2 → not an inversion
  - (i=1, j=3): list[1]=1 = list[3]=1 → not an inversion (equal)
  - (i=0, j=2): list[0]=2 = list[2]=2 → not an inversion (equal)
  - Total: 3 inversions

**Correction**: [2, 1, 2, 1] has 3 inversions, not 4. Verify against the exact definition.

### Example 5: Edge cases

**Input**: [] → sorted = [], inversions = 0

**Input**: [42] → sorted = [42], inversions = 0

**Input**: [2, 2, 2] → sorted = [2, 2, 2], inversions = 0 (all equal, no inversions)

## Notes

**Implementation Strategy**:
- Use the standard recursive merge sort structure:
  1. If the list has 0 or 1 elements, return (list, 0) — base case
  2. Split into left and right halves
  3. Recursively sort and count inversions in each half
  4. Merge the two sorted halves, counting split inversions during the merge
  5. Return total inversions = left_count + right_count + split_count

**Counting Inversions During Merge**:
- Maintain two pointers, one for each sorted half
- When the left pointer element is less than or equal to the right pointer element: take from left, no new inversions
- When the right pointer element is less than the left pointer element: take from right; the number of new inversions equals the number of elements remaining in the left half (all of them are greater than the current right element)
- This works because both halves are already sorted internally

**Why O(n log n)**:
- Each element participates in O(log n) merge steps (one per level of recursion)
- At each merge step, the split inversion count is computed in O(n) by the pointer approach
- Total: O(n log n)

**Common Mistakes**:
- Counting equal elements as inversions (inversion requires strict greater-than)
- Forgetting to accumulate inversion counts from recursive calls (only counting split inversions at each merge, losing sub-half counts)
- Off-by-one in the split point causing uneven halves that lead to incorrect inversion counts
- Modifying the original list instead of working with a copy or returning a new list
- Using a brute-force O(n²) inversion count alongside the merge sort instead of integrating the count into the merge step
- Incorrect merge step that produces wrong sorted order, which then produces wrong inversion counts
