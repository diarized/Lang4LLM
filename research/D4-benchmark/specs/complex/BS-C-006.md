# BS-C-006: Undirected Graph

**Tier**: Complex
**Category**: Data Structures
**Estimated LOC**: 90-130

## Task Description

Implement an undirected graph supporting edge addition, breadth-first traversal, depth-first traversal, cycle detection, and connected component identification. The graph uses integer vertex labels and stores edges as an adjacency structure. All traversals must be deterministic in their starting point but not required to be deterministic in neighbor visit order.

## Requirements

### Functional Requirements

1. Support `add_edge(u, v)` to add an undirected edge between vertices u and v; adding the same edge twice has no effect; self-loops (u == v) are allowed and count as an edge
2. Support `bfs(start)` to return a list of all vertices reachable from the given start vertex, in the order they are first visited during breadth-first traversal; the start vertex is included first
3. Support `dfs(start)` to return a list of all vertices reachable from the given start vertex, in the order they are first visited during depth-first traversal; the start vertex is included first
4. Support `has_cycle()` returning true if the graph contains at least one cycle (including self-loops), false otherwise
5. Support `connected_components()` returning a list of components, where each component is a list of vertices belonging to that component; vertices within each component and the order of components are not required to be sorted; every vertex that has been added via any edge must appear in exactly one component

### Input Specification

- **add_edge(u, v)**: Two integers representing vertex labels — adds an undirected edge; vertices are implicitly created when first referenced in any edge
- **bfs(start)**: Integer vertex label — returns a list of integers (reachable vertices in BFS visit order); if start vertex has no edges and was not added, behavior is defined as returning a single-element list containing start
- **dfs(start)**: Integer vertex label — returns a list of integers (reachable vertices in DFS visit order); same convention for isolated start as bfs
- **has_cycle()**: No parameters — returns true or false
- **connected_components()**: No parameters — returns a list of lists of integers; each inner list is one connected component

### Constraints

- Vertex labels are integers in the range 0 to 10,000
- Number of vertices: 0 to 1,000
- Number of edges: 0 to 10,000
- Graph is undirected (edge u-v implies edge v-u)
- No built-in graph library allowed
- BFS must use a queue structure; DFS must use recursion or an explicit stack

## Examples

### Example 1: BFS and DFS traversal

**Operations**:
```
graph = Graph()
graph.add_edge(1, 2)
graph.add_edge(1, 3)
graph.add_edge(2, 4)
graph.add_edge(3, 4)
graph.bfs(1)   // returns [1, 2, 3, 4] (BFS order from 1)
graph.dfs(1)   // returns [1, 2, 4, 3] or [1, 3, 4, 2] (DFS order, neighbor order varies)
```

**Explanation**:
- BFS visits 1 first, then all neighbors of 1 (2 and 3), then unvisited neighbors of 2 (4 is reached before 3's neighbor 4 is processed)
- DFS visits 1 first, immediately recurses into a neighbor, going deep before backtracking
- Exact DFS order depends on which neighbor is visited first, both orderings shown are valid

### Example 2: Disconnected graph and connected components

**Operations**:
```
graph = Graph()
graph.add_edge(1, 2)
graph.add_edge(2, 3)
graph.add_edge(4, 5)
graph.connected_components()
// returns [[1, 2, 3], [4, 5]]  (components in any order, vertices in any order)
```

**Explanation**:
- Vertices 1, 2, 3 form one component; 4 and 5 form another
- BFS/DFS from vertex 1 would not reach 4 or 5

### Example 3: Cycle detection

**Operations**:
```
// Graph with a cycle
graph = Graph()
graph.add_edge(1, 2)
graph.add_edge(2, 3)
graph.add_edge(3, 1)
graph.has_cycle()   // returns true

// Tree (no cycle)
tree = Graph()
tree.add_edge(1, 2)
tree.add_edge(1, 3)
tree.add_edge(2, 4)
tree.has_cycle()    // returns false
```

**Explanation**:
- A triangle (1-2-3-1) contains a cycle
- A tree with n vertices and n-1 edges has no cycle

### Example 4: Self-loop and duplicate edges

**Operations**:
```
graph = Graph()
graph.add_edge(1, 1)   // self-loop
graph.has_cycle()      // returns true
graph.add_edge(2, 3)
graph.add_edge(2, 3)   // duplicate edge, no effect
graph.connected_components()  // returns [[1], [2, 3]] (any order)
```

**Explanation**:
- A self-loop is a cycle of length 1
- Duplicate edge (2,3) does not add a second edge or create a cycle

## Test Cases

### Required Coverage

2. BFS on a simple path visits vertices in correct BFS order
3. BFS on a disconnected graph visits only reachable vertices from start
4. DFS on a simple path visits vertices in correct DFS order
5. DFS on a graph with branches visits a full branch before backtracking
6. DFS on a graph with a cycle visits each vertex exactly once (no infinite loop)

8. has_cycle on graph with a triangle returns true
9. has_cycle on graph with a self-loop returns true
10. has_cycle on empty graph returns false
11. connected_components on fully connected graph returns one component
12. connected_components on graph with no edges returns empty list or individual single-vertex components per inserted vertices
13. connected_components on graph with two separate components returns two groups
14. add_edge with duplicate edge does not affect traversal or cycle detection
15. BFS and DFS both visit every vertex exactly once in connected graph

## Notes

**Implementation Strategy — Adjacency Representation**:
- Store the graph as a mapping from vertex to a set (or list) of its neighbors
- Use a set for neighbors to naturally deduplicate edges
- When add_edge(u, v) is called, add v to u's neighbor set and u to v's neighbor set

**BFS Implementation**:
- Use a queue (FIFO): enqueue the start vertex, mark it visited
- Dequeue a vertex, record it, enqueue all unvisited neighbors
- Continue until the queue is empty

**DFS Implementation**:
- Use a stack (LIFO) or recursion: mark start vertex visited and record it
- For each unvisited neighbor, recurse (or push and process)
- A visited set prevents revisiting vertices in cyclic graphs

**Cycle Detection**:
- For undirected graphs, run DFS tracking a visited set and the parent of each vertex
- A cycle exists if DFS reaches an already-visited vertex that is not the current vertex's direct parent
- Self-loops: detected immediately because the neighbor equals the current vertex (which is visited)
- Alternative: the graph has a cycle if the number of edges exceeds the number of vertices minus the number of components (forest property)

**Connected Components**:
- Initialize an empty visited set
- For each vertex in the graph, if not visited, start a BFS or DFS from it — all vertices reached form one component
- Repeat until all vertices are visited

**Common Mistakes**:
- Infinite loops in BFS/DFS when visited set is missing or not checked before enqueuing
- Cycle detection counting the parent edge as a back edge (incorrectly reporting a cycle in a tree)
- Not adding the reverse direction of an edge (forgetting undirected means both directions)
- Duplicate edges causing cycle false positives when parent tracking is not used
- connected_components missing vertices that were never involved in any edge (if the graph tracks implicit isolated vertices)
