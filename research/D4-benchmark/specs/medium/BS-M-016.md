# BS-M-016: Dutch National Flag Sort

**Tier**: Medium
**Category**: Algorithms
**Estimated LOC**: 25-35

## Task Description

Given a list of integers and a pivot value, partition the list in place (or return a new list) such that all elements strictly less than the pivot come first, all elements equal to the pivot come next, and all elements strictly greater than the pivot come last. This is known as the Dutch National Flag problem. The relative order within each group does not need to be preserved.

## Requirements

### Functional Requirements

1. Accept a list of integers and a pivot value as input
2. Rearrange or return the elements partitioned into three contiguous groups: [less than pivot | equal to pivot | greater than pivot]
3. All elements less than the pivot must appear before any element equal to the pivot
4. All elements equal to the pivot must appear before any element greater than the pivot
5. Every element in the original list must appear exactly once in the result
6. The pivot value itself may or may not be present in the list — both cases must be handled

### Input Specification

- **numbers**: A list of integers — may be empty, may contain duplicates
- **pivot**: An integer — the partition boundary value
- **Return**: A list of integers in three-group order [less | equal | greater]; order within each group is unspecified

### Constraints

- List length: 0 to 100,000 elements
- Time complexity: O(n) — single pass preferred
- Space complexity: O(1) extra (in-place) or O(n) (new list) — both acceptable
- Do not use a general sort algorithm (that would be O(n log n))
- Duplicates must all appear in the correct group

## Examples

### Example 1: Basic partition

**Input**: numbers = [3, 1, 4, 1, 5, 9, 2, 6, 5], pivot = 5
**Output**: A list where [elements < 5] appear before [elements == 5] before [elements > 5]
**Valid output (one of many)**: [3, 1, 4, 1, 2, 5, 5, 9, 6]
**Explanation**: 3,1,4,1,2 are less than 5; both 5s are equal; 9,6 are greater than 5

### Example 2: Pivot not in list

**Input**: numbers = [1, 3, 5, 7, 9], pivot = 4
**Output**: [elements < 4] then [] then [elements > 4]
**Valid output**: [1, 3, 5, 7, 9]
**Explanation**: No element equals 4; group "equal" is empty; all others stay in their correct region

### Example 3: All elements equal to pivot

**Input**: numbers = [5, 5, 5], pivot = 5
**Output**: [5, 5, 5]
**Explanation**: All elements in the "equal" group; result is unchanged

### Example 4: All elements less than pivot

**Input**: numbers = [1, 2, 3], pivot = 10
**Output**: [1, 2, 3] (any order within group)
**Explanation**: "equal" and "greater" groups are empty

### Example 5: All elements greater than pivot

**Input**: numbers = [8, 6, 7], pivot = 0
**Output**: [8, 6, 7] (any order within group)
**Explanation**: "less" and "equal" groups are empty

### Example 6: Empty list

**Input**: numbers = [], pivot = 3
**Output**: []
**Explanation**: Nothing to partition

### Example 7: Mixed with negatives

**Input**: numbers = [-2, 5, -1, 3, 0, 5], pivot = 0
**Output**: elements < 0 | elements == 0 | elements > 0
**Valid output**: [-2, -1, 0, 5, 3, 5]
**Explanation**: -2 and -1 are less than 0; 0 equals pivot; 5, 3, 5 are greater than 0

## Test Cases

### Required Coverage

- List with elements in all three groups (less, equal, greater)
- Pivot value not present in list (equal group empty)
- All elements equal to pivot
- All elements less than pivot (greater group empty)
- All elements greater than pivot (less group empty)
- Empty input list
- List with negative integers as pivot and/or elements

- Single-element list equal to pivot
- Single-element list not equal to pivot

### Minimum Test Count

10 test cases

## Success Criteria

Implementation passes when:
- [ ] All elements less than pivot appear before all elements equal to pivot
- [ ] All elements equal to pivot appear before all elements greater than pivot
- [ ] Every element from the original list appears exactly once in the result
- [ ] Handles the case where pivot is not present in the list
- [ ] Empty list produces empty result
- [ ] All elements in each group are correctly classified (no element in wrong region)

## Notes

**Common Mistakes**:
- Processing elements that have already been placed into a final group, causing double-counting or incorrect placement
- Not handling duplicate pivot values — they must all end up in the "equal" region
- Off-by-one in pointer management causing one element to be skipped or processed twice
- Swapping into the wrong region (e.g., swapping a "less" element past the "equal" region into the "greater" region)

**Classic O(n) Algorithm (Dijkstra's three-way partition)**:
Maintain three pointers: `lo` (next position for "less"), `mid` (current element), `hi` (next position for "greater"):
- If current element < pivot: swap with lo, advance both lo and mid
- If current element == pivot: advance mid only
- If current element > pivot: swap with hi, retreat hi (do not advance mid; new element at mid not yet classified)
- Stop when mid > hi
