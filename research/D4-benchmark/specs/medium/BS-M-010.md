# BS-M-010: Circular Buffer

**Tier**: Medium
**Category**: Data Structures
**Estimated LOC**: 35-45

## Task Description

Implement a fixed-capacity circular buffer (also called a ring buffer) that stores integers. When the buffer is full and a new value is written, the oldest unread value is silently overwritten. The buffer supports write (add a value) and read (remove and return the oldest value).

## Requirements

### Functional Requirements

1. Create the buffer with a fixed capacity specified at construction time
2. Implement `write(value)` — add an integer to the buffer; if the buffer is full, overwrite the oldest unread value and advance the read position accordingly
3. Implement `read()` — remove and return the oldest value in the buffer; signal an error or return null/none if the buffer is empty
4. Implement `is_empty()` — return true if no unread values remain
5. Implement `is_full()` — return true if the buffer is at capacity and the next write will overwrite data

### Input Specification

- **capacity**: A positive integer (1 to 10,000) — fixed size set at creation
- **write(value)**: An integer — no return value
- **read()**: No input — returns an integer, or null/none/error if empty
- **is_empty()**: No input — returns a boolean
- **is_full()**: No input — returns a boolean

### Constraints

- Capacity is fixed after construction and cannot change
- Overwrite behavior on full buffer must advance the read pointer (oldest value is lost)
- All operations must run in O(1) time
- No dynamic resizing allowed

## Examples

### Example 1: Basic write and read

**Input**: capacity=3, write(1), write(2), write(3), read(), read()
**Output**: read() returns 1, then 2
**Explanation**: Values are read in FIFO order; 3 remains in the buffer

### Example 2: Overwrite when full

**Input**: capacity=3, write(1), write(2), write(3), write(4), read()
**Output**: read() returns 2
**Explanation**: Buffer was full after writing 1,2,3. Writing 4 overwrites 1 (oldest). Buffer now contains [2,3,4]. Read returns 2.

### Example 3: Repeated overwrite

**Input**: capacity=2, write(1), write(2), write(3), write(4), read(), read(), is_empty()
**Output**: read() returns 3, read() returns 4, is_empty() returns true
**Explanation**: After writing 1,2 the buffer is full. Write 3 overwrites 1; write 4 overwrites 2. Buffer contains [3,4].

### Example 4: Read on empty buffer

**Input**: capacity=3, read()
**Output**: error or null/none
**Explanation**: No values have been written; nothing to read

### Example 5: is_full and is_empty transitions

**Input**: capacity=2, is_empty(), write(10), is_full(), write(20), is_full(), read(), is_full()
**Output**: is_empty()=true, is_full()=false, is_full()=true, is_full()=false
**Explanation**: Empty on creation; not full after one write; full after two writes; not full after one read

### Example 6: Capacity of 1

**Input**: capacity=1, write(5), write(9), read()
**Output**: read() returns 9
**Explanation**: Writing 9 overwrites 5 (the only slot). Only 9 remains.

## Test Cases

### Required Coverage

- Write and read values in FIFO order without overflow
- Write causes overwrite when buffer is at capacity
- Read on empty buffer signals error or returns null/none
- is_empty() returns true on new buffer
- is_full() returns true when buffer reaches capacity
- is_empty() returns true after all values are read
- Capacity-1 buffer: single slot overwrite behavior
- Multiple consecutive overwrites (more writes than capacity)
- Interleaved writes and reads that cycle the buffer multiple times
- read() followed immediately by write() to verify pointer wrapping

### Minimum Test Count

10 test cases

## Success Criteria

Implementation passes when:
- [ ] FIFO order preserved for values that have not been overwritten
- [ ] Overwrite correctly discards the oldest value and advances read position
- [ ] read() on empty buffer is handled without undefined behavior
- [ ] is_empty() and is_full() accurately reflect buffer state
- [ ] All operations execute in O(1) time
- [ ] Buffer wraps correctly across multiple cycles of writes and reads

## Notes

**Common Mistakes**:
- Not advancing the read pointer when a write overwrites the oldest value, causing the read pointer to point at new data instead of next oldest
- Confusing the count of stored elements with the read/write pointer positions
- Off-by-one in full/empty detection: using the same state for both leads to ambiguity (common fix: track element count separately from pointers)
- Forgetting to wrap the write or read pointer back to 0 when it reaches the capacity boundary

**Implementation Approach**: Maintain three pieces of state: a fixed-size backing array of length capacity, a write pointer, and either a read pointer or an element count. Using an element count alongside a single write pointer (from which the read position is derived) avoids the full/empty ambiguity.
