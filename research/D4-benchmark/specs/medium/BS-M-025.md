# BS-M-025: String to Integer Parser

**Tier**: Medium
**Category**: String Processing
**Estimated LOC**: 40-55

## Task Description

Parse a string representation of an integer into a numeric integer value without using any built-in string-to-integer conversion functions. The implementation must handle optional leading whitespace, an optional sign character, digit extraction, and overflow conditions by clamping to the representable range.

## Requirements

### Functional Requirements

1. Skip any leading whitespace characters (spaces only) at the start of the string
2. Detect an optional sign character ('+' or '-') immediately after any whitespace
3. Read subsequent digit characters ('0'–'9') to form the integer value
4. Stop reading at the first non-digit character after the digits begin (do not return an error)
5. If no digits are found after skipping whitespace and sign, return 0
6. If the parsed value exceeds the maximum 32-bit signed integer (2,147,483,647), return 2,147,483,647
7. If the parsed value is below the minimum 32-bit signed integer (-2,147,483,648), return -2,147,483,648
8. Do not use any built-in string-to-number conversion functions

### Input Specification

- **s**: A string of arbitrary printable characters
- **Return**: An integer clamped to the range [-2,147,483,648, 2,147,483,647]

### Constraints

- String length: 0 to 200 characters
- Only leading whitespace is skipped; whitespace after the sign or digits stops parsing
- Overflow clamping applies to the final value, not intermediate digits
- Time complexity: O(n) where n is the string length

## Examples

### Example 1: Simple positive integer

**Input**: "42"
**Output**: 42
**Explanation**: Digits read directly; no sign, no whitespace

### Example 2: Negative integer with sign

**Input**: "-91283472332"
**Output**: -2147483648
**Explanation**: Value underflows 32-bit minimum; clamped to -2,147,483,648

### Example 3: Leading whitespace

**Input**: "   42"
**Output**: 42
**Explanation**: Three leading spaces skipped, then "42" parsed

### Example 4: Explicit positive sign

**Input**: "+100"
**Output**: 100
**Explanation**: Plus sign consumed, "100" parsed as positive

### Example 5: Stop at non-digit character

**Input**: "4193 with words"
**Output**: 4193
**Explanation**: Parsing stops at the space after "4193"; trailing text ignored

### Example 6: Non-digit before any digits

**Input**: "words and 987"
**Output**: 0
**Explanation**: First non-whitespace character is not a sign or digit; no digits found, return 0

### Example 7: Overflow positive

**Input**: "2147483648"
**Output**: 2147483647
**Explanation**: Value exceeds maximum 32-bit signed integer by 1; clamped to 2,147,483,647

### Example 8: Empty string

**Input**: ""
**Output**: 0
**Explanation**: No characters to parse; return 0

### Example 9: Only whitespace

**Input**: "   "
**Output**: 0
**Explanation**: Only spaces, no digits found; return 0

### Example 10: Zero with sign

**Input**: "-0"
**Output**: 0
**Explanation**: Negative zero is represented as 0

## Notes

**Common Mistakes**:
- Checking for overflow after multiplication — overflow must be detected before multiplying or adding the next digit to avoid undefined behavior
- Not handling the '+' sign (treating it as an invalid character and returning 0)
- Skipping whitespace in the wrong position — only leading whitespace is skipped, not whitespace after the sign
- Not stopping at first non-digit (e.g., attempting to parse "12 34" as 1234)
- Forgetting that '-0' should return 0, not -0

**Overflow Detection**:
Before multiplying the accumulator by 10 and adding the next digit, check whether the result would exceed the bounds. For positive: if accumulator > (MAX / 10), or if accumulator == (MAX / 10) and next digit > MAX % 10, clamp immediately.

**Edge Case**: The minimum 32-bit value (-2,147,483,648) has a larger absolute value than the maximum (2,147,483,647). Handle the clamping for each sign separately.
