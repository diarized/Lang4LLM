# BS-M-031: CSV Parser

**Tier**: Medium
**Category**: File I/O
**Estimated LOC**: 45-60

## Task Description

Parse a CSV (Comma-Separated Values) string into a structured list of records. The first row of the CSV is treated as the header row defining field names. Each subsequent row becomes a record (map from field name to value). The parser must handle quoted fields that may contain commas or newlines within them.

## Requirements

### Functional Requirements

1. Accept a CSV-formatted string as input
2. Treat the first row as the header row; extract field names from it
3. Parse each subsequent row into a record mapping each field name to its corresponding value
4. Handle quoted fields: a field enclosed in double quotes (`"`) may contain commas and newlines; the enclosing quotes are stripped from the value
5. Handle escaped double quotes within quoted fields: `""` (two consecutive double quotes) inside a quoted field represents a single literal double quote character
6. Return a list of records in the order they appear in the input
7. If the input has only a header row and no data rows, return an empty list
8. Ignore completely empty trailing lines at the end of input

### Input Specification

- **csv_text**: A string containing CSV-formatted data with a header row
- **Return**: A list of records, where each record is a mapping from field name (string) to field value (string)

### Constraints

- Field values are always strings in the output (no type conversion)
- Fields may be quoted or unquoted
- Quoted fields may span multiple lines (embedded newlines)
- Empty unquoted field values (two consecutive commas) become empty strings
- Maximum input size: 1 MB
- Do not use built-in CSV parsing libraries

## Examples

### Example 1: Simple two-column CSV

**Input**:
```
name,age
Alice,30
Bob,25
```
**Output**: [{"name": "Alice", "age": "30"}, {"name": "Bob", "age": "25"}]
**Explanation**: Header defines two fields; two data rows parsed into two records

### Example 2: Quoted field containing a comma

**Input**:
```
name,address
Alice,"123 Main St, Apt 4"
Bob,456 Oak Ave
```
**Output**: [{"name": "Alice", "address": "123 Main St, Apt 4"}, {"name": "Bob", "address": "456 Oak Ave"}]
**Explanation**: The comma inside the quoted address is part of the value, not a field separator

### Example 3: Quoted field containing escaped double quote

**Input**:
```
id,description
1,"He said ""hello"""
```
**Output**: [{"id": "1", "description": "He said \"hello\""}]
**Explanation**: `""` inside a quoted field represents one literal double quote

### Example 4: Empty field values

**Input**:
```
a,b,c
1,,3
```
**Output**: [{"a": "1", "b": "", "c": "3"}]
**Explanation**: Two consecutive commas produce an empty string for field "b"

### Example 5: Header only, no data rows

**Input**:
```
name,age
```
**Output**: []
**Explanation**: No data rows; result is an empty list

### Example 6: Three columns, multiple rows

**Input**:
```
first,last,score
Alice,Smith,95
Bob,Jones,82
Carol,White,78
```
**Output**: [{"first": "Alice", "last": "Smith", "score": "95"}, {"first": "Bob", "last": "Jones", "score": "82"}, {"first": "Carol", "last": "White", "score": "78"}]
**Explanation**: Three data rows parsed into three records with three fields each

- Multiple rows and columns

- Single-column CSV

### Minimum Test Count

10 test cases

## Success Criteria

- [ ] Header row correctly extracted as field names
- [ ] Unquoted fields parsed correctly
- [ ] Quoted fields have surrounding quotes stripped
- [ ] Commas inside quoted fields are not treated as delimiters
- [ ] `""` inside quoted fields becomes a single `"`
- [ ] Empty fields produce empty string values
- [ ] Header-only input returns empty list
- [ ] Trailing empty lines do not produce extra records

## Notes

**Common Mistakes**:
- Splitting rows on newline then splitting fields on comma — fails for quoted fields containing newlines or commas; must use a character-by-character state machine
- Not handling the `""` escape sequence inside quoted fields
- Including the surrounding double quotes in the parsed field value
- Creating an extra empty record for a trailing newline

**Parsing Strategy** (state machine approach):
Maintain a state: `normal` or `in_quoted_field`. In `normal` state, a `"` transitions to `in_quoted_field`. A `,` ends the current field. A newline ends the current row. In `in_quoted_field` state, `""` emits one `"` and stays quoted; a lone `"` ends the quoted field and returns to `normal` state.

**Scope**: This spec implements basic RFC 4180-compatible CSV parsing. It does not require handling of alternative delimiters or byte-order marks.
