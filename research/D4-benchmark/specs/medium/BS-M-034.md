# BS-M-034: Log Level Filter

**Tier**: Medium
**Category**: File I/O
**Estimated LOC**: 35-50

## Task Description

Given a string containing log file content and a minimum log level, return only the log lines whose level is at or above the specified minimum. Log levels have a defined severity order from lowest to highest: DEBUG < INFO < WARN < ERROR. Lines that do not match the expected log line format are excluded from the output.

## Requirements

### Functional Requirements

1. Accept a multi-line string of log content and a minimum level string as input
2. Parse each line to determine its log level
3. Include a line in the output if its log level is at or above the minimum level in severity order
4. Exclude lines that do not match the expected log line format
5. Return the matching lines as a list of strings, preserving their original order
6. The minimum level parameter is case-insensitive

### Log Line Format

A valid log line has the following structure:
```
[LEVEL] message content
```
Where:
- The line starts with `[` immediately followed by a level word (`DEBUG`, `INFO`, `WARN`, `ERROR`), followed by `]`
- A single space follows `]`
- The remainder of the line is the message content (may contain any characters)
- Level words are uppercase in valid lines

### Level Severity Order

From lowest to highest: DEBUG (0) < INFO (1) < WARN (2) < ERROR (3)

A line at level L is included when L's severity >= minimum level's severity.

### Input Specification

- **log_content**: A multi-line string where each line is a log entry or other text
- **minimum_level**: A string — one of "DEBUG", "INFO", "WARN", "ERROR" (case-insensitive)
- **Return**: A list of strings (the matching log lines in original order), excluding malformed lines

### Constraints

- Log content length: up to 1,000,000 characters
- Number of lines: up to 100,000
- Invalid minimum_level value: behavior undefined (may raise error or treat as ERROR)
- Lines with unrecognized level tags (e.g., `[TRACE]`) are treated as malformed and excluded

## Examples

### Example 1: Filter at INFO level

**Input**:
```
[DEBUG] Starting application
[INFO] Server started on port 8080
[WARN] High memory usage detected
[ERROR] Database connection failed
```
minimum_level = "INFO"

**Output**: ["[INFO] Server started on port 8080", "[WARN] High memory usage detected", "[ERROR] Database connection failed"]
**Explanation**: DEBUG is below INFO; INFO, WARN, ERROR are at or above INFO

### Example 2: Filter at ERROR level

**Input**:
```
[DEBUG] Starting application
[INFO] Server started on port 8080
[WARN] High memory usage detected
[ERROR] Database connection failed
```
minimum_level = "ERROR"

**Output**: ["[ERROR] Database connection failed"]
**Explanation**: Only ERROR level meets or exceeds ERROR minimum

### Example 3: Filter at DEBUG level (all included)

**Input**:
```
[DEBUG] Starting application
[INFO] Request received
[ERROR] Disk full
```
minimum_level = "DEBUG"

**Output**: ["[DEBUG] Starting application", "[INFO] Request received", "[ERROR] Disk full"]
**Explanation**: DEBUG includes all levels

### Example 4: Malformed lines excluded

**Input**:
```
[INFO] Valid line
This line has no level tag
[WARN] Another valid line
   [ERROR] Leading spaces make this malformed
[UNKNOWN] Unrecognized level
```
minimum_level = "INFO"

**Output**: ["[INFO] Valid line", "[WARN] Another valid line"]
**Explanation**: Lines without proper `[LEVEL]` prefix and lines with unrecognized levels are excluded

### Example 5: Empty input

**Input**: ""
minimum_level = "WARN"

**Output**: []
**Explanation**: No lines to filter

### Example 6: Case-insensitive minimum level

**Input**:
```
[WARN] Low disk space
[ERROR] Out of memory
```
minimum_level = "warn"

**Output**: ["[WARN] Low disk space", "[ERROR] Out of memory"]
**Explanation**: "warn" treated the same as "WARN"

### Example 7: No lines match minimum level

**Input**:
```
[DEBUG] Verbose output
[INFO] Status update
```
minimum_level = "ERROR"

**Output**: []
**Explanation**: No lines are at ERROR level or above

## Test Cases

### Required Coverage

- Filter at each level (DEBUG, INFO, WARN, ERROR) — four separate tests
- All lines match (minimum = DEBUG)
- No lines match (minimum = ERROR, input has only DEBUG/INFO)
- Malformed lines excluded (no `[LEVEL]` prefix)
- Lines with unrecognized level tags excluded
- Empty input returns empty list
- Case-insensitive minimum level parameter
- Preserves original line order in output
- Lines with message content containing `[` characters not misidentified

### Minimum Test Count

10 test cases

## Success Criteria

- [ ] Correctly applies severity order (DEBUG < INFO < WARN < ERROR)
- [ ] Includes lines at or above minimum level only
- [ ] Excludes malformed lines (no `[LEVEL] ` prefix)
- [ ] Excludes lines with unrecognized level tags
- [ ] Minimum level parameter is case-insensitive
- [ ] Original line order preserved in output
- [ ] Empty input returns empty list

## Notes

**Common Mistakes**:
- Using string comparison for level ordering ("INFO" < "WARN" alphabetically is coincidentally true for these four, but "DEBUG" > "ERROR" alphabetically is incorrect — must use explicit numeric severity mapping)
- Including malformed lines (lines without the proper prefix)
- Treating `[WARN]` at the beginning of a message content as a level marker when the line itself starts with `[INFO]`
- Case-sensitive comparison for the minimum_level parameter

**Level Severity Mapping**:
Assign numeric values: DEBUG=0, INFO=1, WARN=2, ERROR=3. A line with level L and minimum M is included when severity(L) >= severity(M).

**Line Format Check**:
A valid line must start with exactly `[DEBUG] `, `[INFO] `, `[WARN] `, or `[ERROR] ` (bracket, uppercase level word, closing bracket, space). Use startswith checks with each of the four valid prefixes.
