# BS-M-006: Stack Implementation

**Tier**: Medium
**Category**: Data Structures
**Estimated LOC**: 30-40

## Task Description

Implement a stack data structure that supports push, pop, peek, and is_empty operations using a list as the underlying storage. A stack follows Last-In-First-Out (LIFO) order: the most recently added item is the first to be removed.

## Requirements

### Functional Requirements

1. Implement `push(value)` — add a value to the top of the stack
2. Implement `pop()` — remove and return the value at the top of the stack
3. Implement `peek()` — return the value at the top without removing it
4. Implement `is_empty()` — return true if the stack contains no elements, false otherwise
5. `pop()` on an empty stack must signal an error (raise an exception or return a sentinel such as null/none)
6. `peek()` on an empty stack must signal an error or return null/none consistently with `pop()`

### Input Specification

- **push(value)**: Any value — no return value required
- **pop()**: No input — returns the top value, or null/none/error if empty
- **peek()**: No input — returns the top value without removal, or null/none/error if empty
- **is_empty()**: No input — returns a boolean

### Constraints

- Underlying storage must be a dynamic list (not a fixed-size array)
- All operations must run in O(1) amortized time
- No built-in stack types allowed (must implement manually using a list)
- Stack size is unbounded (limited only by available memory)

## Examples

### Example 1: Basic push and pop

**Input**: push(10), push(20), push(30), pop()
**Output**: pop() returns 30
**Explanation**: 30 was the last value pushed, so it is the first popped (LIFO)

### Example 2: Peek does not remove

**Input**: push(5), push(9), peek(), peek(), pop()
**Output**: peek() returns 9, peek() returns 9, pop() returns 9
**Explanation**: peek() does not alter the stack; 9 remains on top until popped

### Example 3: is_empty on fresh stack

**Input**: is_empty()
**Output**: true
**Explanation**: Newly created stack contains no elements

### Example 4: is_empty after push and pop

**Input**: push(42), pop(), is_empty()
**Output**: is_empty() returns true
**Explanation**: After removing the only element the stack is empty again

### Example 5: Pop on empty stack

**Input**: pop() (on empty stack)
**Output**: error or null/none
**Explanation**: No element exists to remove; implementation must not silently succeed

### Example 6: Multiple pushes then full drain

**Input**: push(1), push(2), push(3), pop(), pop(), pop(), is_empty()
**Output**: pops return 3, 2, 1 in that order; is_empty() returns true
**Explanation**: LIFO order reverses insertion sequence; stack is empty after all elements removed

## Test Cases

### Required Coverage

- Push single element, then pop it
- Push multiple elements and verify LIFO order on pop
- peek() returns correct top without changing stack size
- is_empty() returns true on new stack
- is_empty() returns false after push
- is_empty() returns true after all elements popped
- pop() on empty stack signals error or returns null/none
- peek() on empty stack signals error or returns null/none
- Interleaved push and pop operations

### Minimum Test Count

9 test cases

## Success Criteria

Implementation passes when:
- [ ] push() adds elements in correct order
- [ ] pop() returns elements in LIFO order
- [ ] peek() returns top element without removal
- [ ] is_empty() accurately reflects stack state
- [ ] Empty-stack operations are handled without undefined behavior
- [ ] All four operations meet O(1) amortized time

## Notes

**Common Mistakes**:
- Appending to the wrong end of the list (front vs. back) causing O(n) operations
- Forgetting to remove the element in pop() (treating it like peek())
- Not checking for empty stack before pop()/peek(), causing index-out-of-bounds errors
- Returning the wrong end of the list for peek/pop after using the front of the list as "top"

**Design Note**: Using the end (tail) of a list as the top of the stack gives O(1) append and remove-last. Using the front gives O(n) insert and is incorrect for this task.
