# BS-M-008: Linked List Basics

**Tier**: Medium
**Category**: Data Structures
**Estimated LOC**: 40-50

## Task Description

Implement a singly linked list that supports appending to the tail, prepending to the head, deleting the first occurrence of a value, and converting the list to a plain list for inspection. Each node holds an integer value and a reference to the next node.

## Requirements

### Functional Requirements

1. Implement `append(value)` — add a node with the given value at the tail (end) of the list
2. Implement `prepend(value)` — add a node with the given value at the head (beginning) of the list
3. Implement `delete(value)` — remove the first node whose value equals the given value; do nothing if the value is not present
4. Implement `to_list()` — return a plain list of all values in order from head to tail
5. The linked list starts empty

### Input Specification

- **append(value)**: An integer — no return value
- **prepend(value)**: An integer — no return value
- **delete(value)**: An integer — no return value; silently ignores missing values
- **to_list()**: No input — returns a list of integers in head-to-tail order

### Constraints

- Each node must store a value and a next-node reference
- No built-in linked list types allowed
- All operations must traverse only as far as necessary (no unnecessary full traversals)
- Duplicate values are allowed; delete removes only the first occurrence

## Examples

### Example 1: Append and to_list

**Input**: append(1), append(2), append(3), to_list()
**Output**: [1, 2, 3]
**Explanation**: Values are added to the tail in insertion order

### Example 2: Prepend and to_list

**Input**: prepend(3), prepend(2), prepend(1), to_list()
**Output**: [1, 2, 3]
**Explanation**: Each prepend inserts at the head, reversing insertion order

### Example 3: Mixed append and prepend

**Input**: append(10), prepend(5), append(20), prepend(1), to_list()
**Output**: [1, 5, 10, 20]
**Explanation**: State after each operation: [10] → [5,10] → [5,10,20] → [1,5,10,20]

### Example 4: Delete existing value

**Input**: append(1), append(2), append(3), delete(2), to_list()
**Output**: [1, 3]
**Explanation**: Node with value 2 is removed; neighbors are linked directly

### Example 5: Delete head node

**Input**: append(1), append(2), append(3), delete(1), to_list()
**Output**: [2, 3]
**Explanation**: Head node is removed and head pointer updated

### Example 6: Delete tail node

**Input**: append(1), append(2), append(3), delete(3), to_list()
**Output**: [1, 2]
**Explanation**: Tail node is removed and previous node's next becomes null

### Example 7: Delete non-existent value

**Input**: append(1), append(2), delete(99), to_list()
**Output**: [1, 2]
**Explanation**: Value 99 not found; list unchanged

### Example 8: Delete first occurrence only (duplicates present)

**Input**: append(1), append(2), append(2), append(3), delete(2), to_list()
**Output**: [1, 2, 3]
**Explanation**: Only the first node with value 2 is removed

## Test Cases

### Required Coverage

- Append multiple values and verify order
- Prepend multiple values and verify order
- Mixed append and prepend operations
- Delete a value from the middle of the list
- Delete the head node
- Delete the tail node
- Delete a value that does not exist (no error)
- Delete first occurrence when duplicates present
- to_list() on empty list returns empty list
- to_list() on single-element list

### Minimum Test Count

10 test cases

## Success Criteria

Implementation passes when:
- [ ] append() adds nodes at the tail in correct order
- [ ] prepend() adds nodes at the head in correct order
- [ ] delete() removes only the first matching node
- [ ] delete() handles missing values without error
- [ ] to_list() returns values in head-to-tail order
- [ ] Head and tail pointers are correctly updated after all operations

## Notes

**Common Mistakes**:
- Not updating the head pointer when prepending to an empty list
- Not updating the head pointer when deleting the head node
- Losing the reference to the rest of the list when removing a node (breaking the chain)
- Traversing one node too far during delete, causing a null reference error
- Forgetting the case where the list has exactly one node and it is deleted (list becomes empty)

**Node Structure**: Each node needs exactly two fields: a value and a reference to the next node. The next reference of the tail node is null/none.
