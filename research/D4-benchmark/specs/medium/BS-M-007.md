# BS-M-007: Queue Implementation

**Tier**: Medium
**Category**: Data Structures
**Estimated LOC**: 30-40

## Task Description

Implement a queue data structure that supports enqueue, dequeue, front, and is_empty operations using a list as the underlying storage. A queue follows First-In-First-Out (FIFO) order: the oldest item added is the first to be removed.

## Requirements

### Functional Requirements

1. Implement `enqueue(value)` — add a value to the back of the queue
2. Implement `dequeue()` — remove and return the value at the front of the queue
3. Implement `front()` — return the value at the front without removing it
4. Implement `is_empty()` — return true if the queue contains no elements, false otherwise
5. `dequeue()` on an empty queue must signal an error or return null/none
6. `front()` on an empty queue must signal an error or return null/none consistently with `dequeue()`

### Input Specification

- **enqueue(value)**: Any value — no return value required
- **dequeue()**: No input — returns the front value, or null/none/error if empty
- **front()**: No input — returns the front value without removal, or null/none/error if empty
- **is_empty()**: No input — returns a boolean

### Constraints

- Underlying storage must be a dynamic list
- No built-in queue types allowed (must implement manually using a list)
- Queue size is unbounded (limited only by available memory)
- Time complexity: enqueue O(1), dequeue O(1) amortized (or O(n) is acceptable if using a plain list with front-removal)

## Examples

### Example 1: Basic enqueue and dequeue

**Input**: enqueue(10), enqueue(20), enqueue(30), dequeue()
**Output**: dequeue() returns 10
**Explanation**: 10 was the first value enqueued, so it is the first dequeued (FIFO)

### Example 2: Front does not remove

**Input**: enqueue(5), enqueue(9), front(), front(), dequeue()
**Output**: front() returns 5, front() returns 5, dequeue() returns 5
**Explanation**: front() does not alter the queue; 5 remains at the front until dequeued

### Example 3: is_empty on fresh queue

**Input**: is_empty()
**Output**: true
**Explanation**: Newly created queue contains no elements

### Example 4: is_empty after enqueue and dequeue

**Input**: enqueue(42), dequeue(), is_empty()
**Output**: is_empty() returns true
**Explanation**: After removing the only element the queue is empty again

### Example 5: Dequeue on empty queue

**Input**: dequeue() (on empty queue)
**Output**: error or null/none
**Explanation**: No element exists to remove; implementation must not silently succeed

### Example 6: Multiple enqueues then full drain

**Input**: enqueue(1), enqueue(2), enqueue(3), dequeue(), dequeue(), dequeue(), is_empty()
**Output**: dequeues return 1, 2, 3 in that order; is_empty() returns true
**Explanation**: FIFO order preserves insertion sequence; queue is empty after all elements removed

## Test Cases

### Required Coverage

- Enqueue single element, then dequeue it
- Enqueue multiple elements and verify FIFO order on dequeue
- front() returns correct front element without changing queue size
- is_empty() returns true on new queue
- is_empty() returns false after enqueue
- is_empty() returns true after all elements dequeued
- dequeue() on empty queue signals error or returns null/none
- front() on empty queue signals error or returns null/none
- Interleaved enqueue and dequeue operations maintaining FIFO ordering

### Minimum Test Count

9 test cases

## Success Criteria

Implementation passes when:
- [ ] enqueue() adds elements to the back
- [ ] dequeue() returns elements in FIFO order
- [ ] front() returns front element without removal
- [ ] is_empty() accurately reflects queue state
- [ ] Empty-queue operations are handled without undefined behavior
- [ ] FIFO invariant is maintained across all interleaved operations

## Notes

**Common Mistakes**:
- Confusing front and back: enqueuing to the front or dequeuing from the back produces LIFO (stack) behavior instead of FIFO
- Forgetting to remove the element in dequeue() (treating it like front())
- Not checking for empty queue before dequeue()/front(), causing index-out-of-bounds errors
- Off-by-one errors when tracking head/tail indices in an index-based implementation

**Design Note**: A simple list with append-to-back and remove-from-front is the most straightforward implementation. Removing from the front of most list types is O(n), which is acceptable here. For O(1) dequeue, a deque or two-stack approach can be used, but is not required.
