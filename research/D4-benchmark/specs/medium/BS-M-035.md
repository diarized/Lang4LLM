# BS-M-035: Bank Account

**Tier**: Medium
**Category**: Object-Oriented Design
**Estimated LOC**: 45-60

## Task Description

Implement a bank account that encapsulates a balance and a transaction history. The account must support deposits, withdrawals (rejected if insufficient funds), balance queries, and retrieval of the full transaction history with amounts and resulting balances.

## Requirements

### Functional Requirements

1. Create an account with an initial balance (default 0 if not specified)
2. **deposit(amount)**: Add the given amount to the balance
   - Amount must be positive; reject negative or zero deposit amounts (do not modify balance)
   - Record the transaction in history
3. **withdraw(amount)**: Subtract the given amount from the balance
   - Amount must be positive; reject negative or zero withdrawal amounts
   - If the balance would go below zero, reject the withdrawal without modifying the balance
   - Record successful transactions in history; do not record rejected ones
4. **get_balance()**: Return the current balance as a number
5. **get_history()**: Return the list of all successful transactions in the order they occurred
   - Each transaction record contains: type ("deposit" or "withdrawal"), amount, and resulting balance after the transaction
6. Initial balance is not recorded as a transaction in history

### Input Specification

- **initial_balance** (optional): A non-negative number — starting balance (default 0)
- **deposit(amount)**: Positive number — amount to add
- **withdraw(amount)**: Positive number — amount to subtract
- **get_balance()**: Returns a number — current balance
- **get_history()**: Returns a list of transaction records, each containing type, amount, and balance_after

### Constraints

- Balance never goes below zero
- Amount values: positive numbers (integers or floats)
- Transaction history is maintained in insertion order
- All monetary values are treated as exact numbers (no rounding required unless float precision is an issue)
- Reject invalid amounts (zero or negative) silently (no exception required; just do not process)

## Examples

### Example 1: Basic deposit and withdrawal

**Operations**:
- Create account with initial_balance = 100
- deposit(50)
- withdraw(30)
- get_balance() → 120
- get_history() → [{"type": "deposit", "amount": 50, "balance_after": 150}, {"type": "withdrawal", "amount": 30, "balance_after": 120}]

**Explanation**: Deposit brings balance from 100 to 150; withdrawal brings it to 120

### Example 2: Rejected withdrawal (insufficient funds)

**Operations**:
- Create account with initial_balance = 50
- withdraw(100)
- get_balance() → 50
- get_history() → []

**Explanation**: Withdrawal of 100 exceeds balance of 50; balance unchanged; no transaction recorded

### Example 3: Partial success sequence

**Operations**:
- Create account with initial_balance = 0
- deposit(200)
- withdraw(75)
- withdraw(200)
- get_balance() → 125
- get_history() → [{"type": "deposit", "amount": 200, "balance_after": 200}, {"type": "withdrawal", "amount": 75, "balance_after": 125}]

**Explanation**: Second withdrawal (200) rejected because balance is only 125; only two successful transactions recorded

### Example 4: Exact balance withdrawal

**Operations**:
- Create account with initial_balance = 100
- withdraw(100)
- get_balance() → 0
- get_history() → [{"type": "withdrawal", "amount": 100, "balance_after": 0}]

**Explanation**: Withdrawing exactly the full balance is allowed; balance goes to 0

### Example 5: Invalid deposit amount rejected

**Operations**:
- Create account with initial_balance = 50
- deposit(-10)
- deposit(0)
- get_balance() → 50
- get_history() → []

**Explanation**: Negative and zero deposit amounts are rejected; balance and history unchanged

### Example 6: Multiple transactions history

**Operations**:
- Create account
- deposit(100)
- deposit(50)
- withdraw(20)
- get_history() → [{"type": "deposit", "amount": 100, "balance_after": 100}, {"type": "deposit", "amount": 50, "balance_after": 150}, {"type": "withdrawal", "amount": 20, "balance_after": 130}]

**Explanation**: Three successful transactions in history, each with running balance

## Test Cases

### Required Coverage

- Deposit increases balance correctly
- Withdrawal decreases balance correctly
- Withdrawal rejected when amount exceeds balance
- Withdrawal allowed when amount exactly equals balance
- Deposit with negative amount rejected
- Deposit with zero amount rejected
- Withdrawal with negative amount rejected
- get_history() returns transactions in order
- Rejected transactions do not appear in history
- Initial balance set correctly (not in history)
- Account with default initial balance (0)
- Multiple deposits and withdrawals with correct running balances in history

### Minimum Test Count

12 test cases

## Success Criteria

- [ ] Balance updated correctly after successful deposits and withdrawals
- [ ] Insufficient funds withdrawals rejected without modifying balance
- [ ] Invalid amounts (zero or negative) rejected for both deposit and withdraw
- [ ] Successful transactions recorded in history with correct type, amount, and balance_after
- [ ] Rejected transactions not recorded in history
- [ ] Initial balance not recorded as a transaction
- [ ] get_balance() returns current balance at any point
- [ ] get_history() returns complete list in chronological order

## Notes

**Common Mistakes**:
- Recording rejected transactions in history
- Recording the initial balance as a transaction
- Not storing balance_after at transaction time (computing it later leads to errors if balance changes)
- Allowing balance to go negative on a failed check (check before subtracting, not after)
- Treating initial_balance = 0 differently from explicitly passed 0 (both should behave identically)

**Transaction Record Fields**:
Each successful transaction must store at minimum: type (string "deposit" or "withdrawal"), amount (number), and balance_after (number at time of transaction). The order of fields in the record is not specified.

**Balance Check for Withdrawal**:
Before processing a withdrawal, verify `current_balance >= amount`. Only proceed if this condition holds.
