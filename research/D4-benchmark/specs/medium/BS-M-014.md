# BS-M-014: Insertion Sort

**Tier**: Medium
**Category**: Algorithms
**Estimated LOC**: 20-30

## Task Description

Implement the insertion sort algorithm to sort a list of integers in ascending order. Insertion sort builds a sorted sequence one element at a time by taking each element from the unsorted portion and inserting it into its correct position within the already-sorted portion.

## Requirements

### Functional Requirements

1. Accept a list of integers as input
2. Return a new list (or sort in place) with all integers in ascending (non-decreasing) order
3. Implement the insertion sort algorithm specifically — not any other sort
4. Handle duplicate values correctly (they must all appear in the result)
5. Handle an empty list and a single-element list without error

### Input Specification

- **numbers**: A list of integers — may be empty, may contain duplicates, may be given in any order
- **Return**: A list of integers sorted in ascending (non-decreasing) order containing the same elements

### Constraints

- List length: 0 to 10,000 elements
- Integer values: any valid integer (positive, negative, zero)
- Time complexity: O(n²) worst case (expected for insertion sort)
- Space complexity: O(1) extra space (in-place preferred, O(n) copy acceptable)
- Do not use built-in sort functions

## Examples

### Example 1: Unsorted list

**Input**: [5, 2, 8, 1, 9, 3]
**Output**: [1, 2, 3, 5, 8, 9]
**Explanation**: Elements rearranged in ascending order

### Example 2: Already sorted list

**Input**: [1, 2, 3, 4, 5]
**Output**: [1, 2, 3, 4, 5]
**Explanation**: Already sorted; no swaps needed (best case O(n))

### Example 3: Reverse sorted list

**Input**: [5, 4, 3, 2, 1]
**Output**: [1, 2, 3, 4, 5]
**Explanation**: Worst case; every element must be shifted to the front

### Example 4: List with duplicates

**Input**: [3, 1, 4, 1, 5, 9, 2, 6, 5]
**Output**: [1, 1, 2, 3, 4, 5, 5, 6, 9]
**Explanation**: Both duplicate 1s and both duplicate 5s appear in the result

### Example 5: Single element

**Input**: [42]
**Output**: [42]
**Explanation**: Single element is already sorted

### Example 6: Empty list

**Input**: []
**Output**: []
**Explanation**: Empty list returns empty list

### Example 7: Negative integers

**Input**: [-3, 0, -1, 5, -7, 2]
**Output**: [-7, -3, -1, 0, 2, 5]
**Explanation**: Negative values sorted correctly relative to each other and to positive values

## Notes

**Common Mistakes**:
- Off-by-one in the inner loop boundary: shifting one position too far or not far enough
- Overwriting an element before saving it to the key variable, losing a value
- Incorrect comparison direction: using > when < is needed (or vice versa) flips sort order
- Not handling the initial sorted region of size 1 (first element) — the outer loop should start at index 1

**Algorithm Outline** (for reference):
1. Start with the second element (index 1); consider everything before it as "sorted"
2. For each element at position i, save it as the key
3. Shift all sorted elements greater than the key one position to the right
4. Place the key in the now-empty slot

**Note on Stability**: Insertion sort is stable — equal elements preserve their original relative order. This property does not affect correctness for integer lists but is worth noting.
