# BS-M-015: Selection Sort

**Tier**: Medium
**Category**: Algorithms
**Estimated LOC**: 20-30

## Task Description

Implement the selection sort algorithm to sort a list of integers in ascending order. Selection sort works by repeatedly finding the minimum element in the unsorted portion of the list and moving it to the end of the sorted portion.

## Requirements

### Functional Requirements

1. Accept a list of integers as input
2. Return a new list (or sort in place) with all integers in ascending (non-decreasing) order
3. Implement the selection sort algorithm specifically — not any other sort
4. Handle duplicate values correctly (all must appear in the result)
5. Handle an empty list and a single-element list without error

### Input Specification

- **numbers**: A list of integers — may be empty, may contain duplicates, may be given in any order
- **Return**: A list of integers sorted in ascending (non-decreasing) order containing the same elements

### Constraints

- List length: 0 to 10,000 elements
- Integer values: any valid integer (positive, negative, zero)
- Time complexity: O(n²) for all cases (selection sort makes exactly n*(n-1)/2 comparisons)
- Space complexity: O(1) extra space (in-place preferred)
- Do not use built-in sort functions

## Examples

### Example 1: Unsorted list

**Input**: [64, 25, 12, 22, 11]
**Output**: [11, 12, 22, 25, 64]
**Explanation**: Each pass selects the minimum from the remaining unsorted portion

### Example 2: Already sorted list

**Input**: [1, 2, 3, 4, 5]
**Output**: [1, 2, 3, 4, 5]
**Explanation**: Each pass finds that the first element is already the minimum; no swaps needed

### Example 3: Reverse sorted list

**Input**: [5, 4, 3, 2, 1]
**Output**: [1, 2, 3, 4, 5]
**Explanation**: Each pass finds the minimum at the far right and swaps it to the front of the unsorted portion

### Example 4: List with duplicates

**Input**: [3, 1, 4, 1, 5, 9, 2, 6, 5]
**Output**: [1, 1, 2, 3, 4, 5, 5, 6, 9]
**Explanation**: Both duplicate 1s and both duplicate 5s appear in the result

### Example 5: Single element

**Input**: [7]
**Output**: [7]
**Explanation**: Single element list is already sorted

### Example 6: Empty list

**Input**: []
**Output**: []
**Explanation**: Empty list returns empty list

### Example 7: Negative integers

**Input**: [-5, 3, -1, 0, -8, 4]
**Output**: [-8, -5, -1, 0, 3, 4]
**Explanation**: Negative values sorted correctly relative to each other and to positive values

## Notes

**Common Mistakes**:
- Not tracking the index of the minimum (tracking the value alone makes swapping impossible)
- Swapping every time a smaller value is found rather than waiting until the full unsorted portion is scanned
- Off-by-one in the outer loop: stopping one iteration early leaves the last element unplaced
- Performing an unnecessary swap when the minimum is already in its correct position (cosmetic issue, not a correctness bug)

**Algorithm Outline** (for reference):
1. For each position i from 0 to n-2:
   a. Find the index of the minimum value in the sublist from position i to n-1
   b. Swap the element at position i with the element at the minimum index
2. After n-1 passes, the list is sorted

**Comparison with Insertion Sort**: Selection sort always makes exactly n*(n-1)/2 comparisons regardless of input order, while insertion sort is faster on nearly-sorted data. Both have O(n²) worst-case time.
