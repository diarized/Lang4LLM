# BS-M-012: Deque Implementation

**Tier**: Medium
**Category**: Data Structures
**Estimated LOC**: 35-45

## Task Description

Implement a double-ended queue (deque) that supports pushing and popping elements from both the front and the back. All four push/pop operations must be available, plus an is_empty check, allowing the deque to function as both a stack and a queue depending on usage.

## Requirements

### Functional Requirements

1. Implement `push_back(value)` — add a value to the back (tail) of the deque
2. Implement `push_front(value)` — add a value to the front (head) of the deque
3. Implement `pop_back()` — remove and return the value at the back; signal error or return null/none if empty
4. Implement `pop_front()` — remove and return the value at the front; signal error or return null/none if empty
5. Implement `peek_front()` — return the front value without removing it; signal error or return null/none if empty
6. Implement `peek_back()` — return the back value without removing it; signal error or return null/none if empty
7. Implement `is_empty()` — return true if the deque contains no elements

### Input Specification

- **push_back(value)** / **push_front(value)**: Any integer — no return value
- **pop_back()** / **pop_front()**: No input — returns an integer, or null/none/error if empty
- **peek_front()** / **peek_back()**: No input — returns an integer without removal, or null/none/error if empty
- **is_empty()**: No input — returns a boolean

### Constraints

- Underlying storage must be a dynamic list
- No built-in deque types allowed (must implement manually)
- All operations must complete in O(1) amortized time
- Deque size is unbounded (limited only by available memory)

## Examples

### Example 1: Queue behavior (push_back + pop_front)

**Input**: push_back(1), push_back(2), push_back(3), pop_front(), pop_front()
**Output**: pop_front() returns 1, then 2
**Explanation**: FIFO behavior when adding at back and removing from front

### Example 2: Stack behavior (push_back + pop_back)

**Input**: push_back(1), push_back(2), push_back(3), pop_back(), pop_back()
**Output**: pop_back() returns 3, then 2
**Explanation**: LIFO behavior when adding and removing from the same end

### Example 3: push_front reverses insertion order

**Input**: push_front(1), push_front(2), push_front(3), pop_front(), pop_front(), pop_front()
**Output**: returns 3, 2, 1
**Explanation**: Each push_front inserts before previous elements; popping from front yields reverse insertion order

### Example 4: Mixed push_front and push_back

**Input**: push_back(10), push_front(5), push_back(20), push_front(1), peek_front(), peek_back()
**Output**: peek_front() returns 1, peek_back() returns 20
**Explanation**: Sequence of operations: [10] → [5,10] → [5,10,20] → [1,5,10,20]

### Example 5: Pop on empty deque

**Input**: pop_front() (on empty deque)
**Output**: error or null/none
**Explanation**: No elements exist to remove

### Example 6: is_empty transitions

**Input**: is_empty(), push_back(7), is_empty(), pop_front(), is_empty()
**Output**: true, false, true
**Explanation**: Empty on creation, not empty after push, empty after removing the only element

### Example 7: peek operations do not remove

**Input**: push_back(4), push_back(8), peek_front(), peek_back(), pop_front(), pop_front(), is_empty()
**Output**: peek_front()=4, peek_back()=8, then pops return 4 and 8, is_empty()=true
**Explanation**: Both peeks read without removal; elements still present for subsequent pops

## Success Criteria

Implementation passes when:
- [ ] push_back() and pop_back() maintain correct back-of-deque ordering
- [ ] push_front() and pop_front() maintain correct front-of-deque ordering
- [ ] peek operations return correct values without altering state
- [ ] All four push/pop combinations produce correct element ordering
- [ ] Empty-deque operations handled without undefined behavior
- [ ] is_empty() accurately reflects current state

## Notes

**Common Mistakes**:
- Confusing front and back — push_front inserts before all existing elements, not after
- Removing in pop() from the wrong end, turning FIFO into LIFO or vice versa
- Peek implementations that accidentally remove the element
- Not handling the single-element case for pop_back (it must also clear the deque, identical to pop_front)

**Implementation Note**: Using the end (tail) of a list for the back and the front of the list for the front gives correct semantics but O(n) push_front and pop_front. For O(1) amortized performance on all four operations, a doubly linked list or a deque implemented as two stacks can be used. O(n) front operations are acceptable if the spec does not require O(1) for push_front.
