# BS-M-019: Two Sum

**Tier**: Medium
**Category**: Algorithms
**Estimated LOC**: 20-30

## Task Description

Given a list of integers and a target integer, find the two elements in the list whose values sum to the target, and return their indices. The problem guarantees exactly one valid pair exists. The returned indices must be in ascending order (smaller index first).

## Requirements

### Functional Requirements

1. Accept a list of integers and a target integer as input
2. Find the two distinct positions (indices) in the list such that the values at those positions sum to the target
3. Return the two indices as a pair (or two-element list), with the smaller index first
4. Exactly one solution is guaranteed — do not handle the case of multiple or no solutions
5. The same element may not be used twice (both indices must be different)

### Input Specification

- **numbers**: A list of integers — may contain positive, negative, and zero values; may contain duplicates
- **target**: An integer — the required sum
- **Return**: A pair of integers [i, j] where i < j and numbers[i] + numbers[j] == target

### Constraints

- List length: 2 to 100,000 elements
- One valid solution is always present
- The two indices must be distinct (cannot use the same element twice)
- Time complexity target: O(n) using a lookup table; O(n²) brute force is acceptable if clearly implemented
- Integer values: any valid integer

## Examples

### Example 1: Basic case

**Input**: numbers = [2, 7, 11, 15], target = 9
**Output**: [0, 1]
**Explanation**: numbers[0] + numbers[1] = 2 + 7 = 9

### Example 2: Solution not at the start

**Input**: numbers = [3, 2, 4], target = 6
**Output**: [1, 2]
**Explanation**: numbers[1] + numbers[2] = 2 + 4 = 6; 3+3 would need index 0 twice, which is not allowed

### Example 3: Indices returned in ascending order

**Input**: numbers = [3, 3], target = 6
**Output**: [0, 1]
**Explanation**: numbers[0] + numbers[1] = 3 + 3 = 6; duplicate values allowed as long as indices differ

### Example 4: Negative numbers

**Input**: numbers = [-1, -2, -3, -4, -5], target = -8
**Output**: [2, 4]
**Explanation**: numbers[2] + numbers[4] = -3 + (-5) = -8

### Example 5: Mixed positive and negative

**Input**: numbers = [-3, 4, 3, 90], target = 0
**Output**: [0, 2]
**Explanation**: numbers[0] + numbers[2] = -3 + 3 = 0

### Example 6: Target zero with symmetric values

**Input**: numbers = [1, 5, -5, 2], target = 0
**Output**: [1, 2]
**Explanation**: numbers[1] + numbers[2] = 5 + (-5) = 0

### Example 7: Solution at end of list

**Input**: numbers = [1, 2, 3, 4, 5, 6], target = 11
**Output**: [4, 5]
**Explanation**: numbers[4] + numbers[5] = 5 + 6 = 11

## Success Criteria

Implementation passes when:
- [ ] Returns exactly two indices that sum to target
- [ ] Smaller index is returned first (ascending order)
- [ ] Both returned indices are distinct (not the same element used twice)
- [ ] Works for negative integers and zero
- [ ] Handles duplicate values in the list correctly

## Notes

**Common Mistakes**:
- Using the same index twice when a value is exactly half of the target (e.g., target=6, list=[3,5,3]: index 0 and index 2 are valid; 0 and 0 are not)
- Returning indices in descending order instead of ascending
- Off-by-one in loop bounds causing the last element to be skipped
- Not accounting for negative numbers when initializing or checking a lookup table

**O(n) Algorithm (lookup table approach)**:
1. Create an empty map from value to index
2. For each element at index i:
   a. Compute complement = target - numbers[i]
   b. If complement is in the map, return [map[complement], i] (map[complement] < i is guaranteed since it was stored earlier)
   c. Otherwise, store numbers[i] → i in the map

**O(n²) Algorithm (brute force)**:
For each pair (i, j) where i < j, check if numbers[i] + numbers[j] == target. Return [i, j] when found.
