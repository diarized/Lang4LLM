# BS-M-033: Simple Config Parser

**Tier**: Medium
**Category**: File I/O
**Estimated LOC**: 35-50

## Task Description

Parse a configuration text in key=value format into a mapping from key strings to value strings. The parser must support single-line comments starting with `#`, blank line skipping, optional whitespace around the `=` separator, and must reject or ignore malformed lines.

## Requirements

### Functional Requirements

1. Accept a multi-line string of configuration text as input
2. Parse each non-comment, non-blank line as a key=value pair
3. Strip leading and trailing whitespace from both keys and values
4. Lines whose first non-whitespace character is `#` are comment lines — ignore them entirely
5. Blank lines (containing only whitespace) are ignored
6. If a line contains no `=` character, it is malformed — skip it silently
7. The key is everything before the first `=`; the value is everything after the first `=` (allowing `=` characters in values)
8. Duplicate keys: if the same key appears multiple times, the last value wins
9. Return the resulting key-value mapping

### Input Specification

- **config_text**: A multi-line string in key=value format
- **Return**: A mapping from string keys to string values; both keys and values are strings with surrounding whitespace removed

### Constraints

- Key constraints: non-empty after whitespace stripping; may contain letters, digits, underscores, hyphens, dots
- Value constraints: any string (may be empty, may contain `=` characters)
- Line length: up to 1,000 characters
- Total lines: up to 10,000
- Comment delimiter `#` must be the first non-whitespace character on the line (inline comments are not supported)

## Examples

### Example 1: Basic key-value pairs

**Input**:
```
host=localhost
port=8080
debug=true
```
**Output**: {"host": "localhost", "port": "8080", "debug": "true"}
**Explanation**: Three simple key=value pairs, no special cases

### Example 2: Comments and blank lines ignored

**Input**:
```
# Database configuration
host=db.example.com

# Credentials
user=admin
password=secret
```
**Output**: {"host": "db.example.com", "user": "admin", "password": "secret"}
**Explanation**: Comment lines and blank lines are skipped; three pairs remain

### Example 3: Whitespace around separator stripped

**Input**:
```
key1 = value1
key2=value2
  key3  =  value3
```
**Output**: {"key1": "value1", "key2": "value2", "key3": "value3"}
**Explanation**: Spaces around `=` are stripped from both key and value; leading spaces in key also stripped

### Example 4: Value containing equals sign

**Input**:
```
url=http://example.com/path?a=1&b=2
formula=x=y+z
```
**Output**: {"url": "http://example.com/path?a=1&b=2", "formula": "x=y+z"}
**Explanation**: Only the first `=` is the separator; subsequent `=` characters are part of the value

### Example 5: Duplicate key — last value wins

**Input**:
```
timeout=30
timeout=60
```
**Output**: {"timeout": "60"}
**Explanation**: Second definition of "timeout" overrides the first

### Example 6: Empty value

**Input**:
```
empty_key=
another=value
```
**Output**: {"empty_key": "", "another": "value"}
**Explanation**: A key with nothing after `=` has an empty string value

### Example 7: Malformed lines skipped

**Input**:
```
valid=yes
no_equals_sign_here
=no_key
another=ok
```
**Output**: {"valid": "yes", "another": "ok"}
**Explanation**: Line without `=` is skipped; line with empty key (after stripping) is also skipped

### Example 8: Empty input

**Input**: ""
**Output**: {}
**Explanation**: No lines to parse; result is empty mapping

## Test Cases

### Required Coverage

- Basic key=value pairs
- Comment lines starting with `#` (ignored)
- Blank lines (ignored)
- Whitespace around the `=` separator stripped
- Values containing `=` characters (only first `=` is separator)
- Duplicate key (last value wins)
- Empty value (key= with nothing after)
- Malformed line without `=` (skipped)
- Line with empty key after stripping (skipped)
- Empty input (empty result)
- Mixed valid and invalid lines in same input

### Minimum Test Count

11 test cases

## Success Criteria

- [ ] All key=value pairs correctly parsed
- [ ] Comment lines (starting with `#`) are ignored
- [ ] Blank lines are ignored
- [ ] Whitespace stripped from keys and values
- [ ] First `=` is the separator; subsequent `=` in value is preserved
- [ ] Duplicate keys resolved to last value
- [ ] Empty values (empty string) are stored correctly
- [ ] Malformed lines are silently skipped
- [ ] Empty input returns empty mapping

## Notes

**Common Mistakes**:
- Splitting on all `=` characters instead of only the first — splits URLs and formulas incorrectly
- Not stripping whitespace from keys — leads to keys with leading/trailing spaces that don't match expected names
- Treating `#` anywhere in the line as a comment (spec: only when `#` is the first non-whitespace character)
- Not handling the case where a value is empty (nothing after `=`)
- Overwriting instead of replacing on duplicate key (same result, but be intentional)

**Line Processing Order**:
1. Check if line (after stripping) is empty → skip
2. Check if first non-whitespace character is `#` → skip
3. Find first `=` index → if not found, skip
4. Split at first `=`: key = text before, value = text after
5. Strip whitespace from key and value
6. If key is empty after stripping → skip
7. Store in map (overwrite if key already exists)
