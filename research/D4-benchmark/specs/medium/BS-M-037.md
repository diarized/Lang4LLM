# BS-M-037: Simple Iterator

**Tier**: Medium
**Category**: Object-Oriented Design
**Estimated LOC**: 35-50

## Task Description

Implement an iterator over an integer range that supports sequential forward traversal. The iterator is created with a start, end, and optional step value, and supports three operations: checking whether a next value exists, advancing to and returning the next value, and resetting to the beginning of the range.

## Requirements

### Functional Requirements

1. Create an iterator with:
   - **start**: The first value in the range (inclusive)
   - **end**: The last value in the range (exclusive — the range does not include end)
   - **step**: A positive integer indicating how much to advance each time (default 1)
2. **has_next()**: Return true if there is at least one more value to yield; false otherwise
3. **next()**: Advance the iterator and return the current value
   - Returns the current value before any other calls have been made or the value following the previous next() call
   - Calling next() when has_next() is false results in an error (or returns a sentinel such as null)
4. **reset()**: Reset the iterator to the beginning of the range, as if it had just been created
5. Calling next() repeatedly without checking has_next() must still work correctly — the iterator must be safe to drive with next() alone (until exhausted)

### Input Specification

- **start**: An integer — first value (inclusive)
- **end**: An integer — upper bound (exclusive); if end <= start, the range is empty
- **step**: A positive integer — increment between values (default 1)
- **has_next()**: Returns boolean
- **next()**: Returns an integer, or signals error/null if exhausted
- **reset()**: Returns nothing; resets iterator state

### Constraints

- Range values: any integers (positive, negative, zero)
- step must be a positive integer (≥ 1)
- end <= start means an empty range (has_next() returns false immediately)
- The iterator does not store all values in memory; it computes them on demand
- Step may cause the sequence to skip over end without landing exactly on it (the range ends when current + step >= end)

## Examples

### Example 1: Basic range (0 to 5, step 1)

**Iterator**: start = 0, end = 5, step = 1
**Sequence**: next() → 0, next() → 1, next() → 2, next() → 3, next() → 4
**After 5 calls**: has_next() → false
**Explanation**: Range [0, 5) with step 1 yields five values: 0, 1, 2, 3, 4

### Example 2: Step greater than 1

**Iterator**: start = 0, end = 10, step = 3
**Sequence**: next() → 0, next() → 3, next() → 6, next() → 9
**After 4 calls**: has_next() → false
**Explanation**: Stepping by 3: 0, 3, 6, 9; next would be 12 which is ≥ 10, so range ends

### Example 3: Empty range (end <= start)

**Iterator**: start = 5, end = 3, step = 1
**has_next()**: false (immediately)
**next()**: signals error or returns null
**Explanation**: No values to yield when end <= start

### Example 4: Reset to beginning

**Iterator**: start = 1, end = 4, step = 1
**Operations**:
- next() → 1
- next() → 2
- reset()
- next() → 1
- next() → 2
- next() → 3
- has_next() → false

**Explanation**: After reset(), iteration starts from the beginning again

### Example 5: Single value range

**Iterator**: start = 7, end = 8, step = 1
**has_next()**: true
**next()**: 7
**has_next()**: false
**Explanation**: Range [7, 8) contains exactly one value

### Example 6: Negative range

**Iterator**: start = -3, end = 1, step = 1
**Sequence**: next() → -3, next() → -2, next() → -1, next() → 0
**After 4 calls**: has_next() → false
**Explanation**: Negative start is valid; range proceeds normally

### Example 7: Step that skips past end

**Iterator**: start = 0, end = 7, step = 4
**Sequence**: next() → 0, next() → 4
**After 2 calls**: has_next() → false
**Explanation**: After 4, next would be 8 which is ≥ 7; range ends after yielding 0 and 4

## Test Cases

### Required Coverage

- Basic range step 1 (complete traversal)
- Step greater than 1
- Step that skips over end without landing on it
- Empty range (end <= start) — has_next() false immediately
- Single value range (exactly one element)

- Negative start value

### Minimum Test Count

10 test cases

## Success Criteria

- [ ] has_next() accurately reflects remaining values
- [ ] next() returns values in correct sequence with correct step
- [ ] next() on exhausted iterator returns error/null
- [ ] reset() restores iterator to initial state
- [ ] Empty range handled correctly (has_next() = false from start)
- [ ] Step skipping past end does not include values beyond end
- [ ] Negative start values work correctly

## Notes

**Common Mistakes**:
- Off-by-one: including the end value (range is exclusive of end)
- Not tracking current position separately from start — reset() needs to return to start, so both must be stored
- Step skipping: not checking `current + step >= end` correctly when step > 1; the value 'end' itself is never yielded
- Calling next() when has_next() is false is a logic error; implementations may choose to return null, raise an error, or return a sentinel value — the choice must be consistent

**State to Store**:
- start (immutable, for reset)
- end (immutable)
- step (immutable)
- current (mutable, current position or next position to yield)

**has_next() Logic**: Return `current < end`
**next() Logic**: Check has_next(); if false, signal error; otherwise save value at current, advance current by step, return saved value
**reset() Logic**: Set current = start
