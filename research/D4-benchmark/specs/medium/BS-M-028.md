# BS-M-028: Combinations Count

**Tier**: Medium
**Category**: Mathematics
**Estimated LOC**: 30-45

## Task Description

Compute the number of combinations C(n, k), also written as "n choose k", which counts the number of ways to choose k items from a set of n items without regard to order. Use the formula C(n, k) = n! / (k! × (n-k)!) and implement in a way that avoids unnecessary large intermediate values for small inputs.

## Requirements

### Functional Requirements

1. Accept two non-negative integers n and k as input
2. Return C(n, k) = n! / (k! × (n-k)!) as a non-negative integer
3. Return 1 when k = 0 or k = n (only one way to choose zero or all items)
4. Return 0 when k > n (impossible to choose more items than available)
5. Handle the symmetry property: C(n, k) = C(n, n-k); use the smaller of k and n-k to minimize computation
6. Do not use built-in combinatorics functions

### Input Specification

- **n**: A non-negative integer — the total number of items
- **k**: A non-negative integer — the number of items to choose
- **Return**: A non-negative integer representing the number of combinations

### Constraints

- n range: 0 to 30 (guarantees result fits in a 64-bit integer)
- k range: 0 to n (but implementation must also handle k > n by returning 0)
- Do not use built-in factorial or combinatorics functions
- Time complexity: O(k) using the multiplicative formula

## Examples

### Example 1: Choose 2 from 5

**Input**: n = 5, k = 2
**Output**: 10
**Explanation**: C(5,2) = 5! / (2! × 3!) = 120 / (2 × 6) = 10

### Example 2: Choose 0 from any n

**Input**: n = 7, k = 0
**Output**: 1
**Explanation**: There is exactly one way to choose nothing (the empty selection)

### Example 3: Choose all items

**Input**: n = 4, k = 4
**Output**: 1
**Explanation**: There is exactly one way to choose all 4 items from 4

### Example 4: k greater than n

**Input**: n = 3, k = 5
**Output**: 0
**Explanation**: Cannot choose 5 items from a set of 3

### Example 5: n = 0, k = 0

**Input**: n = 0, k = 0
**Output**: 1
**Explanation**: C(0,0) = 1 by convention — one way to choose nothing from nothing

### Example 6: Symmetry property

**Input**: n = 6, k = 4
**Output**: 15
**Explanation**: C(6,4) = C(6,2) = 15; implementation may use k = min(4, 6-4) = 2 internally

### Example 7: n = 10, k = 3

**Input**: n = 10, k = 3
**Output**: 120
**Explanation**: C(10,3) = 10! / (3! × 7!) = 720 / 6 = 120

### Example 8: Boundary case n = 30

**Input**: n = 30, k = 15
**Output**: 155117520
**Explanation**: Largest value within the n ≤ 30 constraint; must not overflow 64-bit integer

## Notes

**Common Mistakes**:
- Computing full factorials and dividing — n! can be astronomically large even for small n; use the multiplicative formula instead
- Floating-point intermediate values — stick to integer arithmetic throughout to avoid rounding errors
- Not exploiting symmetry: C(n, k) = C(n, n-k); using k = min(k, n-k) reduces the number of multiplications

**Multiplicative Formula** (avoids large intermediate factorials):
C(n, k) = (n × (n-1) × ... × (n-k+1)) / (k × (k-1) × ... × 1)
Compute numerator and denominator together by iterating i from 1 to k: multiply result by (n - i + 1) and divide by i at each step. Because C(n, k) is always an integer, each intermediate division is exact.

**Pascal's Triangle Alternative**: Build row by row up to n, storing only the current row. Space O(n), time O(n×k). Suitable for multiple queries but overkill for a single call.
