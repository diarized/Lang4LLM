## Three Core Characteristics (Detailed)

**1. Autonomy**:
- "The ability to independently manage the entire workflow, from task decomposition to coding and debugging"
- Agents handle end-to-end processes without human intervention
- Self-directed planning and execution capabilities

**2. Expanded Task Scope**:
- Beyond generating code snippets to encompass full SDLC
- Requirements analysis → design → implementation → testing → deployment
- Multi-file, multi-module, multi-phase development

**3. Engineering Practicality**:
- "A shift in research emphasis from algorithmic innovation toward practical engineering challenges"
- Focus on system reliability, process management, and tool integration
- Production-ready systems vs. research prototypes

## Agent Architectures

**Single-Agent Systems**:
- Individual LLM managing entire workflow
- Internal planning and execution loops
- Tool integration for code execution, debugging, testing

**Multi-Agent Systems**:
- Collaborative agents with specialized roles
- Division of labor (planner, coder, tester, reviewer)
- Communication protocols between agents
- Coordination mechanisms for complex tasks

**Workflow Components**:
- Active planning - task decomposition and strategy formulation
- Execution - code generation and modification
- Observation - monitoring results and feedback
- Adjustment - iterative refinement based on observations

## Design Implications

1. **Agent-Friendly Language Features**: Support for iterative workflows, clear state representation
2. **Tool Integration Points**: Language should expose debugging, testing, profiling hooks
3. **Multi-File Coherence**: Strong module system, explicit dependencies, interface contracts
4. **Process Visibility**: Observable execution states, introspectable decisions
5. **Error Recovery Patterns**: Language constructs for graceful failure handling and rollback
6. **Contextual Metadata**: Embedded documentation, type information, usage examples

## Agent-Specific Error Patterns (Inferred)

**Planning Errors**:
- Incorrect task decomposition
- Missing dependencies in plan
- Unrealistic subtask assumptions

**Execution Errors**:
- Tool misuse (wrong API calls)
- State management failures (lost context across iterations)
- Multi-file inconsistencies

**Observation Errors**:
- Misinterpreting feedback (test failures, compiler errors)
- Missing critical information in output
- Over-generalizing from partial observations

**Adjustment Errors**:
- Wrong fix strategy (addressing symptoms not root cause)
- Excessive iterations without convergence
- Breaking working code during refinement

**Design Implication**: Language should make these error patterns visible and recoverable
