## Design Decisions

### 1. Verbose vs Debug Flags
**Decision**: Separate flags for different purposes
**Rationale**:
- `--verbose`: Shows compilation phases (parsing, type checking)
- `--debug`: Shows internal AST structure
- Users can combine: `--verbose --debug` for full detail

### 2. Colored Output
**Decision**: Use colored crate for terminal output
**Rationale**:
- Green ✓ for success
- Red ✗ for errors
- Cyan → for progress indicators
- Improves readability and user experience

### 3. AST Pretty-Printing
**Decision**: Use Rust's built-in Debug formatting (`{:#?}`)
**Rationale**:
- Minimal implementation effort
- Consistent with Rust conventions
- Good enough for debugging purposes
- Can be enhanced later if needed

### 4. Parse vs Check Commands
**Decision**: Separate commands instead of flags on single command
**Rationale**:
- Clear intent: "parse" for syntax, "check" for full validation
- Matches common compiler tool patterns (e.g., rustc --parse-only)
- Easier to document and use

## Known Limitations

### 1. No Stdin Support
**Current**: Only reads from files
**Limitation**: Can't pipe source code via stdin
**Future**: Add `lang4llm check -` for stdin input

### 2. No JSON/Machine-Readable Output
**Current**: Human-readable text only
**Limitation**: Hard to integrate with IDE/tooling
**Future**: Add `--format json` for structured output

### 3. No Watch Mode
**Current**: Single-shot execution
**Limitation**: Must re-run manually after file changes
**Future**: Add `--watch` flag for continuous checking
